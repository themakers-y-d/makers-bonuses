## שלב 0. איפה אתה עומד, ועצור אם זו לא המערכת

**קודם כל, על איזה מחשב אתה. אל תשאל אותו, בדוק:** `uname -s`. `Darwin` הוא מק: עבוד לפי מה שמסומן **במק**, דלג על מה שמסומן **בווינדוס**, וכל השאר משותף. `MINGW` או `MSYS` הוא ווינדוס עם Git Bash: להפך.

⛔ **ואם הפקודה עצמה נכשלת, אתה בווינדוס בלי Git for Windows.** אתה רץ ב-PowerShell, וכל פקודה בקובץ הזה תיפול, כולל ה-`ls` שמתחת, שיגיד לך בטעות שזו לא תיקיית MAKERS. זה הדבר הראשון להתקין, לפני כל דבר אחר. **אבל קודם ודא, עדיין ב-PowerShell, שזו באמת תיקיית MAKERS**, כדי לא להתקין כלום על מחשב בתיקייה הלא נכונה: `Test-Path CLAUDE.md, 2-makers\morty\morty.md, 4-learned\state.md, .claude\rules\records.md` חייב להחזיר `True` ארבע פעמים. `False` אחד, ואתה עוצר כמו שכתוב למטה על תיקייה שאינה MAKERS. אחר כך אמור לו מילה במילה: "חסר לך פה רכיב חינמי שמתקינים פעם אחת. אני מתקין אותו בשבילך. אם יקפוץ חלון שמבקש אישור, תלחץ כן ותגיד לי כשזה נגמר." ואז הרץ בעצמך:

```
winget install -e --id Git.Git --accept-source-agreements --accept-package-agreements
```

ההתקנה לוקחת דקה או שתיים, ובזמן הזה אצלו שקט. אם `winget` עצמו לא קיים, או שההתקנה נכשלה או שהחלון נדחה, שלח אותו להוריד את Git for Windows מ-git-scm.com ולהתקין עם כל ברירות המחדל. ⛔ **ואם גם שם נדרשת סיסמת מנהל שאין לו**, וזה קורה במחשב של עבודה, זה לא משהו שנפתור כאן: אמור לו את זה בשורה אחת, תן לו את `hi@themakers.co.il`, ועצור. ⛔ **ואחרי שזה נגמר, קלוד קוד צריך להיסגר לגמרי ולהיפתח מחדש**, כי רק בעלייה הוא מוצא את Git Bash. אמור לו מילה במילה: "סיימתי. עכשיו תסגור את קלוד קוד לגמרי, כולל החלון שהוא פתוח בו, ותפתח אותו שוב באותה תיקייה. ואז תיכנס שוב לקובץ בגיטהאב, github.com/themakers-y-d/makers-bonuses/blob/main/transcripts/INSTALL-makers.md, תלחץ על כפתור ההעתקה ותדביק לי אותו, כמו בפעם הראשונה." ועצור. בפתיחה הבאה `uname -s` יענה, ומתחילים את השלב הזה מחדש.

⛔ **ואם גם אחרי הפתיחה מחדש `uname -s` עדיין נכשל**, אל תתקין שוב, כי זה יחזור בדיוק. בדוק ב-PowerShell אם Git נמצא במקומו: `Test-Path "$env:ProgramFiles\Git\bin\bash.exe"`. אם זה `True`, Git מותקן וקלוד קוד פשוט לא מצא אותו: הרץ `[Environment]::SetEnvironmentVariable('CLAUDE_CODE_GIT_BASH_PATH', "$env:ProgramFiles\Git\bin\bash.exe", 'User')`, ובקש ממנו לסגור ולפתוח שוב פעם אחת, באותו משפט כמו למעלה. אם זה `False`, ההתקנה לא הצליחה: שלח אותו ל-git-scm.com כמו למעלה.

ארבעה קבצים חייבים להתקיים בתיקייה הנוכחית:

```bash
ls CLAUDE.md 2-makers/morty/morty.md 4-learned/state.md .claude/rules/records.md
```

הדפס לבעלים את שם התיקייה ואת מה שמצאת. אם אחד מהם חסר, אמור במשפט אחד שזו אינה תיקיית MAKERS שלו, בקש ממנו לפתוח את קלוד קוד בתיקייה שהוא פותח בכל יום, **ועצור בלי לגעת בכלום.**

**⛔ ואם הכל שם, קבע את נתיב המערכת ושמור אותו גם מחוץ לסשן:**

```bash
VAULT="$(pwd)"; echo "$VAULT" > "$HOME/.makers-transcript-install"; echo "$VAULT"
```

**בווינדוס** הרץ מיד אחריה גם את זו, שכותבת את אותו נתיב בצורה `C:/Users/...` שכל תוכנה במחשב מבינה, ולא בצורה `/c/Users/...` ש-Git Bash מדפיס. במק היא לא עושה כלום:

```bash
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*) VAULT="$(pwd -W)"; echo "$VAULT" > "$HOME/.makers-transcript-install"; echo "$VAULT" ;; esac
```

⛔ **וכל בלוק פקודות מכאן והלאה נפתח בשורה שקוראת את הקובץ הזה בחזרה.** זה נראה חוזר על עצמו והוא לא: כל הרצת טרמינל נפתחת כתהליך חדש, ומשתנה שנקבע בבלוק אחד כבר לא קיים בבלוק הבא. ‏`"$VAULT"` ריק פירושו `git -C ""` שנכשל ברעש, אבל גם `python3 makers/apply-to-vault.py ""` שנפתר בשקט אל תיקיית העבודה, כלומר אל השכפול.

כל פקודה מכאן והלאה משתמשת ב-`"$VAULT"` ולא בנתיב יחסי. **הקובץ הקטן הזה קיים כי בשלב 6 אתה מבקש ממנו לסגור ולפתוח את קלוד קוד, והמשתנה מת שם יחד עם הסשן.** פקודה יחסית שתרוץ אחרי זה תיצור את קובץ ההגדרות בתוך השכפול במקום במערכת. זה לא מחזיר שגיאה. זה פשוט מתקין הכל למקום שאף אחד לא קורא ממנו, וזה הכשל הגרוע ביותר בקובץ הזה.

## שלב 2. מביאים את הערכה

```bash
if [ -d ~/transcript-pipeline/.git ]; then
  git -C ~/transcript-pipeline pull --ff-only
else
  git clone https://github.com/themakers-y-d/transcript-pipeline.git ~/transcript-pipeline
fi
ls ~/transcript-pipeline/makers/apply-to-vault.py ~/transcript-pipeline/INSTALL-MAKERS.md ~/transcript-pipeline/launchd/
```

**בווינדוס בלבד, מכאן ועד הפסקה "שים לב שאין כאן `cd`". במק דלג ישר לשם**: במק אין צורך בפייתון מיוחד, והקובץ הקטן `~/.makers-transcript-python` שמוזכר מכאן והלאה לא נוצר אצלו. כל בלוק שקורא אותו נופל במק בחזרה ל-`python3`, בדיוק כמו תמיד. כל בלוק כאן עטוף בבדיקה של מערכת ההפעלה, כך שגם אם הוא רץ במק בטעות, הוא לא עושה כלום.

**בווינדוס** ה-`ls` בודק את מתזמן המשימות במקום את `launchd/`, ואחריו בדיקה אחת של סופי השורות. כל שורה בה חייבת להסתיים ב-0:

```bash
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*)
  ls ~/transcript-pipeline/makers/apply-to-vault.py ~/transcript-pipeline/INSTALL-MAKERS.md ~/transcript-pipeline/scripts/windows/schedule.ps1
  for f in ~/transcript-pipeline/scripts/*.sh; do printf '%s ' "$f"; tr -cd '\r' < "$f" | wc -c; done ;;
esac
```

**בווינדוס, מספר אחר מ-0** אומר שהסקריפטים ירדו עם סופי שורות של ווינדוס, והעותקים שיגיעו למערכת שלו יגררו את זה איתם. אל תשכפל שוב באותה דרך, כי זה יחזור בדיוק. שכפל פעם אחת עם סופי השורות של הערכה עצמה, ובדוק שוב:

```bash
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*)
  rm -rf ~/transcript-pipeline
  git clone --config core.autocrlf=input https://github.com/themakers-y-d/transcript-pipeline.git ~/transcript-pipeline
  for f in ~/transcript-pipeline/scripts/*.sh; do printf '%s ' "$f"; tr -cd '\r' < "$f" | wc -c; done ;;
esac
```

⛔ **בווינדוס, עוד לפני שלב 3: פייתון אמיתי.** `python3` שם הוא כמעט תמיד קיצור דרך לחנות של מיקרוסופט, שמדפיס Python was not found ויוצא, והערכה נשענת על פייתון בכל לילה. מצא פייתון שעובד:

```bash
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*)
  PY=""; for c in python3 python py; do "$c" -c 'import sys; sys.exit(0 if sys.version_info[0] == 3 else 1)' >/dev/null 2>&1 && { PY="$c"; break; }; done; echo "${PY:-none}" ;;
esac
```

**בווינדוס**, אם יצא `none`, התקן אותו. זו התקנה למשתמש בלבד, בלי חלון אישור, ולפניה אמור לו במשפט אחד שאתה מתקין רכיב חינמי ושהוא לא צריך לעשות כלום:

```bash
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*)
  powershell.exe -NoProfile -Command "winget install -e --id Python.Python.3.12 --scope user --accept-source-agreements --accept-package-agreements"
  "$(cygpath -m "$LOCALAPPDATA")/Programs/Python/Python312/python.exe" --version ;;
esac
```

**בווינדוס**, בין שמצאת פייתון ובין שהתקנת אותו, עכשיו אזורי הזמן והקובץ הקטן. בלי `tzdata` לפייתון בווינדוס אין את השעון של ירושלים, וכל כותרת של מסמך בדרייב נושאת שעה של גריניץ', שעתיים או שלוש מוקדם מדי, בשקט. הבלוק מוצא את הפייתון מחדש בעצמו, כי המשתנה מהבלוק הקודם לא שורד לכאן, ושומר את הנתיב המלא שלו בקובץ קטן, כמו את הנתיב בשלב 0. כל בלוק מכאן והלאה קורא אותו משם:

```bash
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*)
  PY=""; for c in python3 python py "$(cygpath -m "$LOCALAPPDATA")/Programs/Python/Python312/python.exe" "$(cygpath -m "$LOCALAPPDATA")/Programs/Python/Launcher/py.exe"; do "$c" -c 'import sys; sys.exit(0 if sys.version_info[0] == 3 else 1)' >/dev/null 2>&1 && { PY="$c"; break; }; done
  "$PY" -m pip install --user tzdata
  "$PY" -c "import zoneinfo; print(zoneinfo.ZoneInfo('Asia/Jerusalem'))"
  PY="$(cygpath -m "$(PYTHONUTF8=1 "$PY" -c 'import sys; print(sys.executable)' | tr -d '\r')")"
  [ -n "$PY" ] && echo "$PY" > "$HOME/.makers-transcript-python"; cat "$HOME/.makers-transcript-python" ;;
esac
```

**בווינדוס** השורה `Asia/Jerusalem` חייבת להופיע בפלט ולא שגיאה, ואחריה נתיב מלא לקובץ `python.exe`. **במק הבלוק לא מדפיס כלום, וזה התקין: אין צורך בכל זה**, והקובץ הקטן לא נוצר: כל בלוק שקורא אותו נופל במק בחזרה ל-`python3`, בדיוק כמו תמיד, וגם קובץ ריק לא ישבור את זה.

⛔ **שים לב שאין כאן `cd`, ובכוונה.** תיקיית העבודה לא בהכרח שורדת לבלוק הבא, ובדיוק כמו עם `"$VAULT"`, פקודה שמניחה שהיא במקום מסוים רצה בשקט במקום אחר. **כל פקודה שנוגעת בערכה מכאן והלאה היא בנתיב מוחלט, `~/transcript-pipeline/...`**

התנאי אינו קישוט: `git clone` לתיקייה שכבר קיימת נכשל, ואז `cd` מצליח בכל זאת ואתה ממשיך לעבוד מול שכפול ישן בלי שום שגיאה גלויה. וה-`ls` מוודא ששלושת הדברים שתצטרך בהמשך באמת הגיעו.

הערכה יושבת בתיקייה משלה, **מחוץ למערכת**. ריפו שלם בתוך המערכת מבלבל אותה ומקשה עליו לנקות אחר כך.

⛔ **שים לב שיצאת מהמערכת ואתה עומד עכשיו בשכפול.** `"$VAULT"` הוא מה שמחזיק את הדרך חזרה.

## שלב 3. שאל את הערכה באיזה מצב המערכת שלו

**אל תשאל אותו באיזו גרסה הוא.** הוא לא יודע, ואין מספר גרסה בשום קובץ של המערכת. במקום זה, שאל את הערכה. היא בודקת גם את הקבצים וגם את כל העריכות, **וכותבת אפס:**


**"Everything is already in place".** התשתית כבר אצלו, רדומה, מהיום שקיבל את המערכת. **דלג על שלב 5 ולך לשלב 6.** אבל שלב 4 כן רץ אצלו, כי הצינור עומד להתחיל לכתוב לקבצים שלו.

**רשימת שינויים ו-"change(s) outstanding".** הוא קנה לפני שהמתעד נכנס. המשך לפי הסדר.

**ואם הרשימה נפתחת ב-`~ refresh: .claude/skills/check-the-system/SKILL.md`**, הוא מהמחזור הראשון, וקובץ הבדיקה שלו קודם לגרסה שהערכה נכתבה מולה. זה לא דורש ממך כלום. הקובץ הזה שייך למוצר ולא לו, והערכה כבר וידאה שכל שורה בו קיימת גם בגרסה שהיא מביאה, כך ששום דבר שלו לא הולך לאיבוד. אמור לו בשורה אחת שקובץ הבדיקה שלו יתעדכן לגרסה חדשה יותר כחלק מההתקנה, והמשך כרגיל.

**⛔ "not a MAKERS vault".** אתה לא בתיקייה הנכונה. חזור לשלב 0.

**⛔ "older than the version this kit was written against".** חסר לו מייקר שלם, ולכן לחלק מהעריכות אין בכלל לאן ללכת. **אל תעקוף את זה ביד.** אמור בפשטות שהעותק שלו ישן מדי בשביל המתנה הזאת ושזה לא משהו שהוא עשה לא נכון. ⛔ **ואל תעצור בלי לתת לו לאן ללכת:** תן לו את `hi@themakers.co.il` ואמור לו לכתוב מה הסקריפט הדפיס, מילה במילה. זה הרגע היחיד בהתקנה שבו לקוח משלם נתקע בלי דרך להתקדם, ולקוח שנתקע בלי כתובת לא חוזר.

**⛔ "the right files, but some of them have been reworded".** זה קורה כשמישהו ערך את הקבצים שלו אחרי שקיבל את המערכת, והוא פתיר. ⛔ **אבל אל תתקן כאן.** התיקון הוא כתיבה לקבצים שלו, והשלב הזה הבטיח לו שהוא קריאה בלבד. רשום לעצמך את רשימת הקבצים שסחפו, **לך לשלב 4 ועשה נקודת חזרה, והתיקון עצמו קורה בשלב 5.** תיקון לפני נקודת החזרה נראה בשלב 4 כמו "עבודה שלו שלא נשמרה", עלול להיבלע ב-stash, ושובר את ההבטחה בשלב 12 שהחזרה מחזירה למצב שלפני ההתקנה.

וכך מתקנים, כשתגיע לשם: השגיאה מונה בשורה נפרדת כל קובץ שסחף **ומצטטת את תחילת השורה שהיא חיפשה.** חפש את הציטוט הזה בתוך `~/transcript-pipeline/makers/apply-to-vault.py`, ולידו יושב הטקסט המלא להוספה. ואז פתח את הקובץ שלו ומצא את **המשפט שאומר את אותו דבר בניסוח שלו**, ושים את התוספת מיד אחריו, בדיוק במקום שבו הסקריפט היה שם אותה. ⛔ **אתה לא משחזר את נוסח העוגן המקורי ולא כותב מחדש את המשפט שלו, אתה רק מוסיף.** ואם בקובץ שלו אין בכלל משפט שאומר את אותו דבר, כלומר הוא נמחק ולא נוסח מחדש, **עצור והתייחס לזה כמו לעותק ישן מדי**: אין מקום מקביל, וניחוש שם הוא בדיוק מה שהסקריפט מסרב לעשות. ואז, **בשלב 5 ולא כאן**, הרץ את הבדיקה היבשה שוב. **היא עצמה הבדיקה שכיסית הכל**, כי בכל הרצה היא מונה מחדש את כל מה שחסר, והיא מחפשת גם את הטקסט המוסף ולא רק את העוגן. כל עוד היא מתלוננת, נשאר משהו. ⛔ **ואם אחרי הוספה שנראית לך נכונה היא עדיין מתלוננת על אותו קובץ, עצור ואל תמשיך.** זה בדיוק המקום שבו סוכן מחליט "מספיק טוב". אל תדלג על אף עריכה: חלק מהן נכשלות בשקט כשמפספסים אותן, ושורה שחסרה בטבלת ניתוב לא זורקת שגיאה לעולם.

**⛔ ומכאן והלאה, הסמכות אינה הפקודות שכתובות כאן.** הסמכות היא `2-makers/vibecoder/refs/transcript-infrastructure.md`, שנוחת אצלו בשלב 5 ויושב כבר אצל מי שדילג עליו. הוא מתאר תשעה חלקים שחייבים להתקיים, למה כל אחד שם, ומה זה נראה כשהוא חסר. מתכון עובד בדיוק כל עוד שום דבר לא זז, וברגע שמשהו זז, קובץ הסיבות הוא מה שנשאר.

## שלב 4. נקודת חזרה, לפני שנוגעים בקובץ אחד

הצינור עומד להתחיל לכתוב לקבצים שלו לבד, בלי שאף אחד מסתכל. הבטיחות כאן אינה אישור, היא הפיכות. **השלב הזה רץ בשני המסלולים**, גם אצל מי שאין לו מה להתקין.

```bash
VAULT="$(cat "$HOME/.makers-transcript-install")"
git -C "$VAULT" rev-parse --show-toplevel 2>/dev/null
git -C "$VAULT" status --short
```

⛔ **השורה הראשונה חייבת להחזיר את `"$VAULT"` עצמו ולא נתיב שמעליו.** מערכת שיושבת בתוך ריפו אחר מחזירה `true` לכל בדיקה תמימה, ואז הקומיט ושורת החזרה מכוונים לעץ הלא נכון, והבעלים מקבל הבטחת ביטול ששייכת למשהו אחר. אם חזר נתיב אחר, אמור לו את זה ועצור.

**בווינדוס, לפני כל אחד מהמצבים שלמטה:** Git שהותקן זה עתה לא יודע בשם מי לחתום על קומיט, ואז כל קומיט נכשל, גם של ההתקנה וגם של הריצות הליליות. הבלוק נותן לו שם, רק אם אין כבר, ומדפיס אותו. במק הוא לא עושה כלום:

```bash
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*) git config --global user.email >/dev/null 2>&1 || { git config --global user.name "$USERNAME"; git config --global user.email "owner@localhost"; }; git config --global user.name ;; esac
```

**אין ריפו.** בקש אישור מפורש ל-`git init`, כי זה שינוי במכונה שלו:

```bash
VAULT="$(cat "$HOME/.makers-transcript-install")"
git -C "$VAULT" init && git -C "$VAULT" add -A && git -C "$VAULT" commit -m "המערכת לפני חיבור התמלולים"
```

⛔ **ואם הוא מסרב, ההתקנה נעצרת כאן.** הסופג מסרב לרוץ בלי נקודת שחזור, ובצדק, ואין מסלול עוקף. אמור לו את זה בשורה אחת בלי להתנצל על התכנון.

**יש ריפו והעץ נקי.** קח את המזהה הקיים ואל תיצור קומיט חדש:

```bash
VAULT="$(cat "$HOME/.makers-transcript-install")"
git -C "$VAULT" rev-parse --short HEAD
```

**⛔ יש ריפו ויש בעץ עבודה שלא נשמרה.** אל תעשה `git add -A` בשקט. הראה לו את רשימת הקבצים, אמור שאתה עומד לשמור אותם יחד כנקודת חזרה, וחכה לתשובה. קומיט שגורף פנימה עבודה פתוחה הופך את הביטול המתועד לדבר שהורס אותה. **ואם הוא אומר לא**, זו תשובה לגיטימית: בקש ממנו לסיים או לשמור ולחזור אליך, או הצע `git stash` שמסלק את זה הצידה ומחזיר בפקודה אחת. **אם השתמשת ב-stash, רשום לעצמך להחזיר אותו** עם `git -C "$VAULT" stash pop` אחרי שלב 9, ואמור לו את זה בשלב 12. **וייתכן שזה יתנגש**, כי שלב 5 ערך בינתיים חלק מאותם קבצים. התנגשות אינה אובדן: העבודה שלו עדיין ב-`git stash list`. אמור לו, ופתרו אותה יחד לפני שאתה מוסר. עבודה פתוחה ששכחת בצד היא בדיוק מה שמרגיש אחר כך כמו קבצים שנעלמו.

הדפס לו את מזהה הקומיט ושמור אותו אצלך. ⛔ **ואל תבטיח לו עדיין שזה מחזיר הכל**, כי לבדו הוא לא: ההתקנה בשלב 5 מוסיפה קבצים חדשים שגיט עוד לא מכיר, וחזרה לקומיט הזה תשאיר אותם על הדיסק. הדרך הנכונה נסגרת בסוף שלב 5.

## שלב 5. מחילים, ומקמטים את ההתקנה

⛔ **אם שלב 3 מצא קבצים שסחפו, זה המקום לתקן אותם**, עכשיו כשיש נקודת חזרה. לפי ההוראה שבשלב 3, ואז בדיקה יבשה חוזרת עד שהיא שותקת. ורק אז:

⛔ **ואם שלב 3 עצר על קובץ הבדיקה והבעלים אמר שאף שורה שם אינה שלו**, או ששמרת את שלו, הוסף `--refresh-check-the-system` בסוף שתי השורות, גם בבדיקה היבשה החוזרת וגם בהחלה שלמטה. בלי הדגל הבדיקה היבשה תמשיך לעצור על אותו קובץ, ואל תחכה שתשתוק.


אידמפוטנטי. לא דורס אף קובץ קיים, והרצה שנייה לא משנה כלום. היוצא מן הכלל היחיד הוא קובץ בדיקה ישן מהמחזור הראשון, שמתחלף כמו שתואר בשלב 3.

הוא מעתיק את המתעד, שני סקילים, שלוש דלתות, שני קבצי מאגר, את מדריך התשתית ואת הסקריפטים עצמם אל `.claude/scripts/` שבמערכת, ואז מחיל את העריכות הכירורגיות.

**הסקריפטים רצים מתוך המערכת ולא מתוך השכפול.** כל סקריפט פותר את התיקייה של עצמו, ולכן ההגדרות, קובץ המעקב ופעימת החיים נוחתים לידו: בתוך המערכת הם בתוך גיט, מגובים והפיכים. מחוץ לה הם לבד, וקובץ מעקב שאבד מעלה מחדש כל פגישה שהבעלים אי פעם הקליט. ועוד, הוא פותח את המערכת בכל יום ולא את השכפול, ומכונה שהוא לא רואה היא מכונה שהוא לא יכול לכבות.

⛔ **ועכשיו קמט את ההתקנה בקומיט משלה. זה מה שהופך אותה להפיכה באמת:**

```bash

git -C "$VAULT" commit -q -m "צינור התמלולים הותקן"

```

`git add -A` בטוח כאן ורק כאן, כי שלב 4 כבר שמר או הסיט הצידה את כל מה שהיה פתוח, כלומר העץ היה נקי רגע לפני ההחלה. **מה שנכנס לקומיט הזה הוא בדיוק מה שהערכה עשתה ולא שורה מעבר.**

⛔ **שמור את המזהה הזה, והוא ולא זה משלב 4 הוא מה שמבטל את ההתקנה.** ‏`git revert` שלו מוחק את הקבצים שנוספו **וגם** מחזיר את העריכות. חזרה לקומיט של שלב 4 לבדה מחזירה את העריכות ומשאירה את הקבצים, וזה בדיוק המצב הגרוע ביותר: שורת המתעד יוצאת מטבלת הניתוב בזמן שהדלתות שלו נשארות ב-`.claude/commands/`, כלומר אי-התאמת הספירה ששלב 11 מגדיר כשבירה.

⛔ **ומי שדילג על השלב הזה כי הכל כבר היה אצלו אין לו קומיט התקנה**, ואצלו הביטול הוא מחיקת קובץ ההגדרות והורדת שתי הריצות, כי זה כל מה שנוסף.

הקבצים במקום. הסגירה והפתיחה היא שלב 6, והיא רצה גם אצל מי שדילג על השלב הזה.

## שלב 6. סוגרים ופותחים את קלוד קוד, מחזירים את הנתיב, ובודקים שני דברים

⛔ **השלב הזה רץ בשני המסלולים, וזו כל הסיבה שהוא נפרד.** סקילים ומחברים נטענים בעלייה בלבד, כך שגם מי שלא התקין כלום חייב לעלות מחדש כדי ששני החשבונות שהדליק בשלב 1 יופיעו. דילוג כאן נראה אחר כך כמו "המחבר לא עובד" במקום "לא אתחלת".

⛔ **וקודם כל, לפני שאתה מבקש ממנו לסגור, שמור את קובץ ההרצה על הדיסק.** הקובץ הזה הודבק לצ'אט, והסגירה מוחקת אותו יחד עם הסשן. בלעדיו הסוכן החדש עולה ריק: בלי השלבים שנשארו, בלי הקידומות, ובלי לדעת איפה עצרתם, ואצל מי שהגיע משלב 5 גם אחרי שהקבצים כבר שונו. זו התקנה שמתה באמצע.

⛔ **אל תשחזר אותו מהזיכרון.** הוא כ-30 אלף תווים, ושחזור כזה נכשל בשקט: סוכן מקצר או מפרפרז, והעותק שנוחת חסר בדיוק את השלב שיידרש. משוך אותו:

## שלב 7. תיקיית הדרייב, וקובץ ההגדרות

שאל אותו:

## שלב 8. המעלה רץ פעם ראשונה, מולו

כשזה נגמר, הדפס לו כמה מסמכים נוצרו ובאיזו תיקייה. הוא אמור לראות אותם בדרייב שלו.

## שלב 10. תזמון, ושתי ההתראות

עכשיו, ורק עכשיו, זה הופך לאוטומטי.

⛔ **ואמור לו לפני שאתה מתחיל שהשלב הזה מחזיק שתי המתנות של עד תשע דקות כל אחת**, כי הן מחכות לריצה אמיתית של המתזמן. שקט שם הוא התשובה הטובה, ולא סימן שמשהו נתקע.

**תיקיית הלוגים**, שכל הבדיקות למטה קוראות ממנה: **במק** `$HOME/Library/Logs`, ושם גם קובצי ה-`.health`. **בווינדוס** `%LOCALAPPDATA%\transcript-pipeline\logs`, וב-Git Bash `"$(cygpath -u "$LOCALAPPDATA")/transcript-pipeline/logs"`, ושם גם קובצי ה-`.health`. בכל מקום למטה שכתוב `<תיקיית הלוגים>`, זו התיקייה של המחשב שלו. ושמות הקבצים בה זהים בשני המחשבים: `transcript-uploader.stdout.log`, `transcript-uploader.stderr.log`, `transcript-absorber.stdout.log`, `transcript-absorber.stderr.log`, ו-`<LABEL_PREFIX>-uploader.health` ו-`<LABEL_PREFIX>-absorber.health`.

⛔ **השלב הזה מתפצל לפי המחשב שבדקת בשלב 0, והפיצול הוא הדבר הראשון אחרי תיקיית הלוגים שמעליו.** **במק** עבוד לפי הפסקאות שמסומנות **במק**, ודלג על אלה שמסומנות **בווינדוס**. **בווינדוס** דלג ישר לפסקה שמתחילה ב"**בווינדוס, הרישום**", ואל תמלא ואל תטען שום תבנית. מהפסקה "ברירת המחדל" והלאה הכל משותף, והבלוקים שם בוחרים את הפקודה לפי המחשב בעצמם, חוץ משתי פסקאות: האבחון כשהריצה לא התחילה, שמסומן **בווינדוס**, והוכחת ההתראה בסוף השלב, שמסומנת **במק** ו**בווינדוס**.

**במק:** מלא את שתי התבניות מ-`~/transcript-pipeline/launchd/` והנח אותן ב-`~/Library/LaunchAgents/`, אחרי שהבלוק שמתחת יצר אותה ואת תיקיית הלוגים. ארבעת המקומות למילוי מתועדים בראש כל תבנית: התווית, **הנתיב המוחלט לסקריפט שבתוך `"$VAULT"`**, ‏`PATH` מפורש, ותיקיית לוגים אמיתית.

**במק:** ⛔ **וצור את תיקיית הלוגים לפני הטעינה**, אחרת הריצה נכשלת בלי שאף אחד יראה למה, וזה הקובץ היחיד שאתה נשלח לקרוא בהמשך השלב:

```bash
mkdir -p "$HOME/Library/Logs" "$HOME/Library/LaunchAgents"
```

(וגם את `~/Library/LaunchAgents`, שבמק שעוד לא טען אף ג'וב פשוט לא קיימת, וההעתקה של התבניות אליה נכשלת.)

**במק:** התוויות נגזרות מ-`LABEL_PREFIX` שב-`config.sh` בתוספת שם הריצה. אל תמלא אותן מהזיכרון, גזור אותן:

```bash
VAULT="$(cat "$HOME/.makers-transcript-install")"
. "$VAULT/.claude/scripts/config.sh"; echo "${LABEL_PREFIX}-uploader"; echo "${LABEL_PREFIX}-absorber"
```

אם יצא `-uploader` בלי שם לפניו, `LABEL_PREFIX` לא מולא בשלב 7. חזור לשם לפני שאתה טוען משהו.

**במק:** ⛔ **ושם הקובץ חייב להיות זהה לתווית שבתוכו**, כלומר `<LABEL_PREFIX>-uploader.plist` מחזיק `Label` בדיוק כזה. חוסר התאמה נטען בלי שגיאה ואז `kickstart` לא מוצא אותו. **ושמור את השעות שבתבנית כמו שהן** אלא אם הוא ביקש אחרת: הן נבחרו כך שהמעלה מספיק לסיים, והזזה שלהן היא הדרך הקלה לשבור את זה.

**במק:** ⛔ **`PATH` אינו פרט.** המתזמן של מק מנקה אותו, ובלי ערך מפורש הריצה נכשלת בלי שאף אחד יודע. **ארבעה כלים נדרשים:** ‏`claude`, ‏`node`, **`git`**, כי הסופג עושה קומיט בסוף כל ריצה, **ו-`python3`**, כי המעלה בונה בו כל פגישה. קח את ארבעת המיקומים מהמכונה ולא מזיכרון:

```bash
which claude node git python3
```

**במק:** ⛔ **ואם המערכת שלו יושבת בתוך iCloud** (נתיב שמכיל `Library/Mobile Documents`), אמור לו את זה במשפט אחד: ריצה מתוזמנת צריכה הרשאת גישה מלאה לדיסק כדי לכתוב לשם, וקובץ שהענן פינה מהמחשב נראה לסקריפט כמו קובץ חסר. זה לא חוסם, אבל זה מסביר תקלה שאחרת נראית אקראית.

**במק**, הטעינה עצמה:

**במק** הבלוק הזה רץ פעמיים, פעם לכל ריצה: קודם עם התווית של `-uploader` ואז עם זו של `-absorber`. שתי הפעמים חייבות להחזיר בלוק מ-`launchctl print`, וריצה אחת שנטענה היא חצי צינור שנראה שלם.

```bash
LABEL="<התווית שגזרת למעלה>"
launchctl bootout gui/$(id -u)/"$LABEL" 2>/dev/null || true
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/"$LABEL".plist
launchctl print gui/$(id -u)/"$LABEL" | head -5
grep -o '/[^<]*transcript-[a-z]*\.sh' ~/Library/LaunchAgents/"$LABEL".plist | while IFS= read -r f; do ls -l "$f"; done
```

**במק:** ⛔ **השורה הראשונה שם כדי שהניסיון השני לא ייראה כמו שבירה.** ‏`bootstrap` על ג'וב שכבר טעון מחזיר `Bootstrap failed: 5: Input/output error`, וזה קורה בכל תיקון `PATH` ואצל כל מי שהתשתית כבר הייתה אצלו. השורה השנייה מוכיחה שהטעינה עבדה. **⛔ השלישית מוכיחה שה-plist מצביע לסקריפט שבתוך המערכת ולא לאחד שבשכפול**, וזה קריטי כי שלב 12 מוחק את השכפול. תקלה כזאת לא מופיעה בהתקנה, היא מופיעה שבוע אחריה. הלולאה שם ולא `xargs`, כי נתיב המערכת מכיל לרוב רווחים ו-`xargs` מפצל עליהם.

**בווינדוס, הרישום.** אין launchd, אין plist ואין `~/Library`, ולכן כל מה שמסומן **במק** למעלה מוחלף בבלוק אחד. הוא רושם את שתי הריצות במתזמן המשימות של ווינדוס, באותן שעות בדיוק, יוצר את תיקיית הלוגים בעצמו, ומדפיס מיד את שתיהן:

```bash
VAULT="$(cat "$HOME/.makers-transcript-install")"
. "$VAULT/.claude/scripts/config.sh"; echo "LABEL_PREFIX=$LABEL_PREFIX"
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*) powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$(cygpath -w "$VAULT/.claude/scripts/windows/schedule.ps1")" -Action install -LabelPrefix "$LABEL_PREFIX" -ScriptsDir "$(cygpath -m "$VAULT/.claude/scripts")" ;; esac
```

⛔ **שני בלוקים חייבים לחזור**, אחד לכל ריצה, ובכל אחד שורת `runs:` שמצביעה לסקריפט שבתוך `"$VAULT"`. זה מה שמחליף כאן את `launchctl print` ואת בדיקת ה-plist: בלוק חסר, `ERROR` או `NOT REGISTERED` אומרים שלא נרשם, ושגיאה שהקובץ `schedule.ps1` לא קיים אומרת ששלב 5 לא העתיק אותו: הרץ את שלב 5 שוב, ונתיב שמצביע לשכפול יישבר בשלב 12. אותה בדיקה בכל רגע אחר היא `-Action status` באותה שורה, בלי `-ScriptsDir`. את `PATH` אין צורך למלא: הריצה עולה דרך `bash -l` של Git for Windows, והסקריפטים מוצאים את `claude` ואת פייתון בעצמם. הריצה רצה גם על סוללה, ריצה שהוחמצה בשינה רצה כשהמחשב מתעורר, ואין חלון שקופץ בשעת הריצה. ⛔ **ואם `LABEL_PREFIX=` חזר ריק**, קובץ ההגדרות לא מולא בשלב 7: חזור לשם, כי שם ריק נרשם בשקט כמשימות בשם `-uploader`.

**בווינדוס:** **ואם המערכת שלו יושבת בתוך OneDrive** (נתיב שמכיל `OneDrive`, וזה נפוץ כשהיא על שולחן העבודה או במסמכים), אמור לו את זה במשפט אחד: קובץ ש-OneDrive פינה לענן נראה לסקריפט כמו קובץ חסר. זה לא חוסם, אבל זה מסביר תקלה שאחרת נראית אקראית.

**בווינדוס:** **ואם שכבת ההרשאות חוסמת את הבלוק**, תן לו שורה אחת להדביק ב-PowerShell, בתחביר שלו ובנתיבים המלאים (את הנתיב לסקריפט נותן `cygpath -w "$VAULT/.claude/scripts/windows/schedule.ps1"`, ואת התיקייה `cygpath -m "$VAULT/.claude/scripts"`): `powershell -NoProfile -ExecutionPolicy Bypass -File "C:\...\.claude\scripts\windows\schedule.ps1" -Action install -LabelPrefix <LABEL_PREFIX> -ScriptsDir "C:/.../.claude/scripts"`. ולפני כן אמור לו מילה במילה: "תלחץ על כפתור ההתחלה, תכתוב PowerShell ותלחץ Enter. ייפתח חלון עם סמן מהבהב. תדביק שם את השורה עם קליק ימני, ותלחץ Enter. בסוף יודפסו שתי פסקאות קצרות, וזה הסימן שזה עבד."

ברירת המחדל, בתבניות של מק ובמתזמן של ווינדוס כאחד: המעלה פעם אחת בלילה ב-22:10, הסופג פעמיים, ב-08:30 וב-22:40. **המעלה תמיד לפני הסופג, ולפחות שלושים דקות ביניהם**, כי בניית המסמכים לוקחת זמן וסופג שרץ מוקדם מדי סורק תיקייה שעוד לא התמלאה. **אמור לו בקול את שתי השעות שבחרת**, כי "פעמיים ביום" הוא לא משהו שהוא יכול לבדוק, ושעה כן.

⛔ **ועכשיו החלק שנוטים לדלג עליו, וזו הסיבה שאנשים מגלים חודש אחר כך שכלום לא רץ.** כל מה שהוכחת עד כאן הוכח בטרמינל שלך, שיש בו סביבה מלאה. המתזמן מריץ בסביבה נקייה אחרת לגמרי, ו-`launchctl print` במק, או `-Action status` בווינדוס, מוכיח שהג'וב **נטען**, לא שהוא **מצליח**. אלה שני דברים שונים, והפער ביניהם הוא כל הכשלים של `PATH` וההרשאות.

⛔ **ותן לו משהו אמיתי לעשות, אחרת ההוכחה עוברת ריקה.** אחרי שלב 9 קובץ המעקב מלא, כך שריצה מתוזמנת לא תמצא כלום חדש, תכתוב פעימת חיים ותצא בהצלחה **בין אם הגיעה לדרייב ובין אם לא**. זה בדיוק הכשל ששלב 9 מזהיר ממנו, ובלי השורה הבאה הוא נכנס לתוך ההוכחה עצמה.

אז מחק עוד שורה אחת מקובץ המעקב, **ורק אז** הרץ את הסופג דרך המתזמן. **לפני שאתה מוחק, רשום את המזהה, ושלוף מהדרייב את שם המסמך שלו** בכלי ה-metadata של המחבר, כי בדיקה ב למטה משווה את הדוח לפגישה הזאת בדיוק:

```bash
VAULT="$(cat "$HOME/.makers-transcript-install")"
tail -3 "$VAULT/.claude/scripts/absorber-state.txt"   # בחר שורה, מחק אותה ביד
```

⛔ **ושני בלוקי ההמתנה בשלב הזה רצים עד תשע דקות כל אחד. הרץ כל אחד מהם בכלי ה-Bash עם timeout של 600000**, עשר דקות, שהיא התקרה של הכלי. בברירת המחדל, שתי דקות, הכלי קוטע את ההמתנה באמצע, וזה נראה בדיוק כמו "לא התחיל".

⛔ **ורשום את פעימת החיים לפני, בדיוק כמו במעלה.** הסופג רץ ידנית בשלב 9 לפני דקות, אז "שורה עם השעה של עכשיו" עוברת גם אם הג'וב כלל לא התחיל:

```bash
VAULT="$(cat "$HOME/.makers-transcript-install")"
HB="$VAULT/.claude/scripts/absorber-heartbeat.txt"
BEFORE="$(cat "$HB" 2>/dev/null)"
case "$(uname -s)" in
  Darwin) launchctl kickstart -k gui/$(id -u)/<LABEL_PREFIX>-absorber ;;
  *) powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$(cygpath -w "$VAULT/.claude/scripts/windows/schedule.ps1")" -Action run -LabelPrefix "<LABEL_PREFIX>" -Job absorber ;;
esac
for i in $(seq 1 36); do
  AFTER="$(cat "$HB" 2>/dev/null)"; [ "$AFTER" != "$BEFORE" ] && break; /bin/sleep 15
done
if [ "$AFTER" = "$BEFORE" ]; then echo "לא השתנה אחרי תשע דקות. קודם בדוק אם הג'וב עדיין רץ (במק launchctl print, בווינדוס -Action status): רץ = חכה עוד, לא רץ = לא התחיל, ואז במק בדוק PATH ותווית, בווינדוס ראה את האבחון מתחת לבלוק"
elif printf '%s' "$AFTER" | grep -q "LAST RUN FAILED"; then echo "רץ ונכשל. קרא את השורה ואת הלוג"
else echo "רץ והצליח דרך המתזמן"; fi
```

הבלוק מפעיל את הריצה דרך `launchctl` במק ודרך מתזמן המשימות בווינדוס, לבד.

**בווינדוס, אם הודפס "לא השתנה"**, `PATH` אינו הסיבה. הרץ את שורת הסטטוס, והיא אומרת מה קרה:

```bash
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*) VAULT="$(cat "$HOME/.makers-transcript-install")"; powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$(cygpath -w "$VAULT/.claude/scripts/windows/schedule.ps1")" -Action status -LabelPrefix "<LABEL_PREFIX>"; L="$(cygpath -u "$LOCALAPPDATA")/transcript-pipeline/logs"; tail -5 "$L/transcript-absorber.stderr.log"; cat "$L/"*.health ;; esac
```

**בווינדוס:** `result=0x41303` אומר שהריצה לא התחילה בכלל, בדרך כלל כי המשתמש לא היה מחובר או שהמחשב ישן. כל תוצאה אחרת מוסברת בשורות האחרונות של הלוג ובקובץ ה-`.health`. ואם גם זה לא מסביר, אל תנחש: תן לו את `hi@themakers.co.il` עם הפלט הזה, ועצור. מה שכבר במקום נשאר, והוא הפיך.

⛔ **א. פעימת החיים השתנתה, והשורה החדשה אינה `LAST RUN FAILED`.** זה מה שהבלוק למעלה מדפיס, ורק התוצאה השלישית שלו נחשבת.

⛔ **ב. נחת דוח מהריצה הזאת.** זה מה שמפריד בין "הג'וב נטען" לבין "הג'וב הגיע לדרייב וכתב", ופעימת חיים לבדה לא מפרידה ביניהם. **אל תסמוך על ספירת קבצים**: שתי הריצות של היום עשויות ליפול על אותו שם ולדרוס זו את זו, ולכן `ls -lt` ולא `ls -t`. מה שמוכיח הוא שזמן השינוי שמודפס שם מאוחר מההפעלה, **ושהדוח מזכיר את הפגישה שאת השורה שלה בדיוק מחקת.**

⛔ **ג. לדוח הזה יש מספרים פתוחים ותיוגי ודאות.** זו הפעם היחידה בכל ההתקנה שהשערים נבחנים בסביבה שבה הם באמת יחיו: המתזמן רץ מתיקיית עבודה אחרת משלך, ו-`PROTOCOL_FILE` ב-`config.sh` הוא **נתיב יחסי למערכת** ולא לתיקייה שממנה רצים. אם הדוח הידני משלב 9 היה מלא והדוח הזה ריק מהם, זה הנתיב.

⛔ **ד. הלוג נקי משגיאות.** אם יש `.health` בתיקיית הלוגים, קרא אותו, הוא נכתב רק בכישלון. במק, ברוב המקרים זה `PATH` שחסר בו אחד מארבעת הכלים.

**ואותו דבר למעלה, כי גם לו יש הגדרות והרשאות משלו** (במק `PATH` ותווית, בווינדוס משימה משלו במתזמן). ⛔ **ופה צריך זהירות אחת:** הרצת אותו ידנית בשלב 8 לפני כמה דקות, כך שפעימת החיים שלו כבר טרייה, ו-`cat` עליה ייראה זהה בין אם הג'וב רץ ובין אם הוא כלל לא התחיל. אז רשום את החותמת לפני, והשווה אחרי:

⛔ **ואצלו אסור לאלץ עבודה כמו שאילצת אצל הסופג.** למעלה אין בדיקת קיום בדרייב, הוא רק יוצר. מחיקת שורה מקובץ המעקב שלו תעלה את אותה פגישה שוב כמסמך שני, בתיקייה שאולי משותפת, והסופג יספוג אותה פעמיים. התכנון מבטיח שהעלאה כפולה בלתי אפשרית מבנית, ואל תשבור את זה ביד. אז:

```bash

HB="$VAULT/.claude/scripts/uploader-heartbeat.txt"

  /bin/sleep 15
done
if [ "$AFTER" = "$BEFORE" ]; then echo "לא השתנה אחרי תשע דקות. קודם בדוק אם הג'וב עדיין רץ (במק launchctl print, בווינדוס -Action status): רץ = חכה עוד, לא רץ = לא התחיל, ואז במק בדוק PATH ותווית, בווינדוס ראה את האבחון מתחת לבלוק"
elif printf '%s' "$AFTER" | grep -q "LAST RUN FAILED"; then echo "רץ ונכשל. קרא את השורה ואת הלוג"
else echo "רץ והצליח דרך המתזמן"; fi
```

⛔ **שלוש תוצאות ולא שתיים.** פעימת חיים שהשתנתה אומרת שהג'וב התחיל, לא שהוא הצליח: ריצה שנפלה כותבת גם היא שורה, והיא מתחילה ב-`LAST RUN FAILED`. רק השלישית היא הצלחה. **והמתנה בלולאה ולא המתנה קבועה**, כי ריצה איטית שמדווחת "לא התחיל" שולחת אותך לרדוף אחרי באג שלא קיים.

⛔ **ועכשיו ההוכחה שהוא הגיע ל-Wispr ולא רק התחיל.** בלוג שלו נכתבת שורת `worklist:` רק אחרי שהחשבון נמנה בפועל:

```bash
grep -E "worklist:|starting via" "<תיקיית הלוגים>/transcript-uploader.stdout.log" | tail -4
```

שורת `worklist: N of M new meeting(s)` אומרת שהוא קרא את החשבון וידע כמה יש. חסרה, והוא יצא בהצלחה, פירושו שלא הגיע למקור.

⛔ **אל תדלג על זה.** מעלה ששותק משאיר את התיקייה בדרייב ריקה, הסופג לא מתלונן כי המעקב שלו כבר זרוע, והבעלים הולך הביתה עם "מחובר" ומגלה חודש אחר כך.

ואז בקש ממנו לאשר התראות, ⛔ **וזו פעולה שלו ולא שלך.** במק זה חלון ההרשאה של המק. בווינדוס בדרך כלל אין מה לאשר, רק לוודא שההתראות לא חסומות, וזה כתוב למטה. ואז הוכח שהן באמת מופיעות:

**במק:**

```bash
osascript -e 'display notification "צינור התמלולים מחובר" with title "MAKERS"'
```

**במק**, אם לא קפצה התראה, שלח אותו להגדרות המערכת ולאשר התראות לטרמינל, ונסה שוב. הכשל הרועש כאן הוא התראה, וריצה שמפסיקה להתחיל לא יכולה להתלונן בלעדיה.

**בווינדוס** ההוכחה היא הבלוק הזה, וההתראה קופצת בפינה הימנית התחתונה של המסך, מעל השעון:

```bash
VAULT="$(cat "$HOME/.makers-transcript-install")"
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*) TP_TITLE="MAKERS" TP_MSG="צינור התמלולים מחובר" powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$(cygpath -w "$VAULT/.claude/scripts/windows/schedule.ps1")" -Action notify-test ;; esac
```

**בווינדוס**, אם לא קפצה: ההתראה בווינדוס היא ToastNotification של Windows PowerShell, ולכן היא רשומה על שם Windows PowerShell ולא על שם הצינור. אמור לו מילה במילה: "תלחץ על כפתור ההתחלה, תכתוב התראות ותלחץ Enter. תוודא שההתראות דלוקות, ש'נא לא להפריע' כבוי, ושברשימה Windows PowerShell מסומן כמותר." ונסה שוב.

## שלב 11. בדיקת המערכת, רישום הכלי, ומעבר אחרון

```
/check-the-system
```

לא אתה מדווח שזה תקין, הבדיקה שלו מדווחת. המתעד חייב להופיע בטבלת הצוות של מורטי, ומספר הפקודות חייב להיות שווה למספר הסקילים ועוד מספר המייקרים. **אם הספירה לא מסתדרת**, כמעט תמיד חסרה דלת אחת ב-`.claude/commands/`. הרץ שוב, בנתיב מוחלט כי אתה במערכת:

```bash
VAULT="$(cat "$HOME/.makers-transcript-install")"
PY="$(cat "$HOME/.makers-transcript-python" 2>/dev/null)"; [ -n "$PY" ] || PY=python3
"$PY" ~/transcript-pipeline/makers/apply-to-vault.py "$VAULT"
```

הוא ישלים מה שחסר בלי לדרוס כלום. **ואם גם אחרי זה היא לא מסתדרת, זו שבירה של המערכת עצמה ולא של הצינור, והיא של ריק.** אל תנפה את זה חי מול הבעלים, ואל תמשיך למסור כאילו הכל תקין.

ואז שורה אחת ל-`tools.md` בשורש המערכת, לפי `/connect-a-tool`: מה זה, מה זה יכול, **שזה כותב**, התאריך, ואיך מכבים. שורה אחת בטבלה הקיימת, בלי לשכתב את הקובץ.

ולבסוף:

```
/final-pass
```

זה נגע בחשבונות חיים והתקין מכונה שכותבת לקבצים שלו בלי שאף אחד מסתכל. לא מוסרים דבר כזה בלי המעבר האחרון.

## שלב 12. סגירה מולו, ומה קורה בפעם הבאה

ארבע שורות קצרות, בשפה שלו:

הפגישות שלו מגיעות לצוות פעמיים ביום, לבד, והוא לא צריך לעשות כלום.

הצוות מציע לו כללים קבועים ולא כותב אותם בעצמו לרשימה שנטענת בכל סשן.

**ותן לו את שתי דרכי החזרה, כתובות במלואן, ואת ההבדל ביניהן.**

לבטל ריצה אחת, וזו זו שהוא ירצה כמעט תמיד, עם המזהה שתפסת בשלב 9:

```bash
git -C "<הנתיב למערכת שלו>" revert --no-edit <מזהה הריצה>
```

ולהסיר את ההתקנה כולה: **קודם** מורידים את שתי הריצות המתוזמנות בשורות הכיבוי שבסוף השלב הזה, מתחת ל"וכיבוי הוא בקשה אחת ממך", **ורק אז** החזרה שבבלוק הבא, עם מזהה קומיט ההתקנה משלב 5. הסדר נחוץ בשני המחשבים: במק ריצה שנשארה טעונה מול סקריפטים שהחזרה מחקה נכשלת כל לילה, ובווינדוס מתג הכיבוי עצמו יושב בקבצים שהחזרה מוחקת. זה לך, לא משפט אליו:

```bash
git -C "<הנתיב למערכת שלו>" revert --no-edit <מזהה ההתקנה>
rm -f "<הנתיב למערכת שלו>/.claude/scripts/config.sh"
```

⛔ **אמור לו במפורש שהשנייה חזקה מהראשונה**, כדי שלא יפעיל אותה כשהוא רוצה רק לבטל לילה אחד. קובץ המעקב ופעימות החיים נשארים ב-`.claude/scripts/`, אינם מזיקים, ואפשר למחוק אותם ביד.

**ואם בשלב 4 השתמשת ב-stash ועוד לא החזרת אותו אחרי שלב 9**, זה המקום, כמו שהבטחת שם: `git -C "$VAULT" stash pop`, ואמור לו במשפט אחד שהעבודה הפתוחה שלו חזרה למקומה. אם יש התנגשות, העבודה עדיין ב-`git stash list`, ופותרים אותה יחד לפני שמוסרים.

ואמור לו איפה הדוחות נערמים: `3-work/now/transcript-absorption/`, אחד או שניים ביום. זו תיקיית פרויקט רגילה, אז כשהיא נעשית עמוסה מעבירים ישנים ל-`_process/` או ל-`3-work/done/`. ⛔ **אבל את התיקייה עצמה לא מארכבים ולא משנים לה שם כל עוד הצינור דלוק**, כי הריצה כותבת לנתיב הזה, ונתיב מת הוא כשל שקט.

וכיבוי הוא בקשה אחת ממך: להוריד את שתי הריצות המתוזמנות. אלה שורות הכיבוי, ואתה מריץ אותן בעצמך כשהוא מבקש. **במק**, שתי הריצות ושני קובצי ה-plist שלהן:

```bash
launchctl bootout gui/$(id -u)/<LABEL_PREFIX>-uploader
launchctl bootout gui/$(id -u)/<LABEL_PREFIX>-absorber
rm -f ~/Library/LaunchAgents/<LABEL_PREFIX>-uploader.plist ~/Library/LaunchAgents/<LABEL_PREFIX>-absorber.plist
```

**בווינדוס** אין קבצים למחוק, רק שתי משימות במתזמן, ושורה אחת מורידה את שתיהן. הסקריפט שלה יושב במערכת שלו, ב-`.claude/scripts/windows/`, ולא בשכפול, ולכן מתג הכיבוי שורד את מחיקת השכפול בסוף השלב הזה. היא מדפיסה `removed: both scheduled jobs are gone`:

```bash
case "$(uname -s)" in MINGW*|MSYS*|CYGWIN*) powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$(cygpath -w "<הנתיב למערכת שלו>/.claude/scripts/windows/schedule.ps1")" -Action uninstall -LabelPrefix "<LABEL_PREFIX>" ;; esac
```

**בווינדוס**, ואם הוא רוצה אותה לעצמו, להדבקה בחלון PowerShell ולא דרכך, זו אותה שורה בתחביר שלו, עם הנתיב המלא שלו: `powershell -NoProfile -ExecutionPolicy Bypass -File "C:\...\.claude\scripts\windows\schedule.ps1" -Action uninstall -LabelPrefix <LABEL_PREFIX>`.

המתעד יכול להישאר בצוות ולקבל תמלול ביד, או לצאת. התמלולים שכבר נספגו נשארים, כי זה מה שהצוות למד. שום דבר כאן אינו בלתי הפיך.

**ובפעם הבאה הוא לא חוזר לקובץ הזה.** הסקיל `connect-transcripts` יושב עכשיו במערכת, והוא יירה לבד כשהבעלים יגיד במילים שלו שהוא רוצה לחבר, לנתק או לתקן משהו בצינור. אמור לו את זה במשפט אחד לפני שאתה מוסר.

ולבסוף נקה אחריך:

```bash
VAULT="$(cat "$HOME/.makers-transcript-install")"
rm -f "$VAULT/3-work/now/transcript-absorption/_process/INSTALL-makers.md"
rm -rf ~/transcript-pipeline "$HOME/.makers-transcript-install" "$HOME/.makers-transcript-python"
```

העותק ששמרת בשלב 6 היה חבל הצלה לסגירה והפתיחה, וסיים את תפקידו. השאירו אותו והוא יקרא בעוד חצי שנה כאילו הוא הוראות חיות.

מה שנלמד כאן עובר לארכיונאי כשורה מוצעת, לא נכתב ישירות.

## שלב 13. וכשמשהו שקט מדי, שלוש שאלות לפני הכל

השלב הזה לא רץ בהתקנה. הוא רץ בשבוע שבו הבעלים אומר שהוא לא רואה דוחות, בסשן אחר לגמרי.

⛔ **ולכן אין לך כאן את `"$VAULT"` משלב 0, והקובץ הקטן ההוא כבר נמחק.** אתה עומד בתיקיית MAKERS שלו, כי זו התיקייה שהוא פותח. קבע אותו מחדש לפני כל דבר אחר:

```bash
ls CLAUDE.md 2-makers/morty/morty.md >/dev/null && VAULT="$(pwd)" && echo "$VAULT"
```

**א. האם התיקייה בדרייב ריקה?** ריקה פירושה שהמעלה מת, לא שהיה שבוע שקט. זו כל הסיבה שהתיקייה הזאת מוקדשת רק לתמלולים.

**ב. האם הרשימה שחזרה מהדרייב קצרה מקובץ המעקב?** שום דבר לא נמחק משם לעולם, אז קצרה יותר פירושה קריאה חלקית, וקריאה חלקית מאבדת מסמכים בשקט.

**ג. מתי נכתבה פעימת החיים האחרונה?** יש שתיים, אחת לכל צד, ושתיהן ב-`.claude/scripts/` שבמערכת:

```bash
cat .claude/scripts/uploader-heartbeat.txt .claude/scripts/absorber-heartbeat.txt
```

נתיבים יחסיים כאן, ובכוונה: הקובץ הקטן מ-`$HOME` נמחק בשלב 12, ואתה עומד בתיקיית MAKERS שלו ממילא.

ריצה שמפסיקה להתחיל היא הכשל היחיד שלא יכול להתלונן, והגיל של השורות האלה הוא הדבר היחיד שתופס אותו. שורה שמתחילה ב-`LAST RUN FAILED` אומרת לך גם מה קרה ומאיזו נקודת שחזור לחזור.

ושבירה אמיתית של המערכת עצמה היא של **ריק**, המייקר שמתקן את המערכת, ולא ניפוי חי בצ'אט מול הבעלים.
