# מורטי, זה אליך

הבעלים הביא מתנה של MAKERS להתקנה. הקובץ הזה כתוב אליך כדי שלא תצטרך להבין לבד מה לעשות. הבעלים לא צריך לקרוא אותו.

## מה זה, בשורה אחת

מישהו מגיב מילה על ריל או עונה לסטורי, ומקבל הודעה פרטית עם הלינק. אופציונלית רק אחרי שהוא עוקב.

המנוע הוא Zernio, שותפה רשמית של מטא. אין אפליקציית מטא לפתוח, אין שרת, אין מסד נתונים ואין טוקן לתחזק.

## ההחלטות שכבר נעשו בשבילך

אל תבזבז עליהן שאלות.

**הערכה יושבת במקום קבוע:** `~/makers-bonuses`, בתיקיית הבית שלו, מחוץ למערכת. בווינדוס זה `$HOME\makers-bonuses`, וב-Git Bash אותו `~/makers-bonuses`. לא ליד תיקיית המערכת ולא בתוכה. כל פקודת `node kit/...` כאן רצה מתוך `~/makers-bonuses/ig-dm-automation`. ⛔ **אל תחפש את הערכה בדיסק.** היא נמצאת באחד משלושה מקומות בלבד, ושלב 0 עובר עליהם לפי הסדר.

**מי מבצע, לפי המערכת שלו:** בגרסאות קודמות של המערכת יש מייקר בשם הווייבקודר, ובחדשות אין. שלב 0 בודק את זה ואתה עובד לפי הכללים של המערכת שמולך, לא נגדם.

• **בלי ווייבקודר:** אתה מבצע הכל בעצמך, בשיחה הראשית, כולל כל פקודה.

• **עם ווייבקודר:** במערכת הזו הכלל הוא שמה שרץ ומתחבר לחשבון חי עובר אליו. אז אתה מנהל את השיחה, וכל מה שדורש את הבעלים נשאר אצלך: השאלות, ההרשמה, אישור החיבור, הנוסחים, אישור התוכנית והבדיקה עם חבר. הפקודות שרצות בלי שיחה עוברות לווייבקודר בשלוש העברות קבועות, שכתובות בשלבים 5, 7 ו-8. הוא עובד בחלון משלו ולא יכול לשאול את הבעלים כלום, ולכן כל שאלה נשאלת לפני ההעברה, ובבריף אליו כתוב שהבעלים כבר אישר.

**הפרויקט:** `3-work/now/ig-dm/`. אם התיקייה כבר קיימת, עובדים בתוכה ולא יוצרים תאומה לידה.

**סמן ההתקנה:** `3-work/now/ig-dm/_process/install-in-progress.md`. המערכת שלו מזהה בתחילת כל שיחה קובץ בפרויקט שחדש מהשורה האחרונה ב-`4-learned/log.md` כעבודה שלא נסגרה. לכן סשן חדש, גם אחרי סגירה ופתיחה, יודע שיש התקנה באמצע. אתה כותב אותו בשלב 0.5, מעדכן אותו בכל פעם שאתה עוצר לחכות לבעלים, ומוחק אותו בשלב 9.

**הסקילים שנטענים:** ‏`/connect-a-tool` (זו התחברות לחשבון חי) ובסוף `/ship-it-live` (זה נוגע בחשבון אמיתי ושולח הודעות לאנשים). את שניהם מריץ מי שהכלל במערכת שלו קובע: עם ווייבקודר הוא, בלי ווייבקודר אתה. אותו דבר לשורה ב-`tools.md`: היא נכתבת רק דרך `/connect-a-tool`, על ידי מי שהכלל שם נוקב בשמו.

**השאלות:** שלוש, כתובות מילה במילה בשלב 2. שאל אותן בגל אחד ואל תוסיף עליהן.

**מה נשמר בסוף:** קובץ עם מילות המפתח והנוסחים ב-`3-work/now/ig-dm/` עם שם מתוארך, והבעלים יודע איפה הוא.

## איך מדברים איתו

**כל מה שהבעלים קורא, בעברית.** גם משפט לפני פקודה, גם עדכון באמצע וגם תוצאה של בדיקה. פלט של הכלי באנגלית לא מודבק לו, אתה אומר אותו במשפט עברי. לכל בדיקה שהוא רואה כתוב בשלב שלה המשפט שאומרים.

**פנה אליו בלשון זכר**, אלא אם הוא כותב על עצמו בלשון נקבה, ואז בלשון נקבה. בחר פעם אחת והישאר עם זה עד הסוף.

**ותגיד לו מראש על חלונות האישור.** קלוד קוד יבקש ממנו לאשר פקודות שנוגעות בתיקיות מחוץ למערכת. אמור לו פעם אחת, בשלב 0, לפני הבקשה הראשונה: "קלוד קוד יבקש ממך כמה פעמים אישור להריץ פקודה. כשמופיעות בה המילים makers-bonuses, ig-dm, node או git, מאשרים. בקשה אחרת שלא ברורה לך, אל תאשר ותשאל אותי."

ואז הערכה. עבור על שלושת המקומות לפי הסדר, ועצור בראשון שמתאים:

```bash

find 3-work/in -maxdepth 4 -name INSTALL-makers.md -path '*ig-dm-automation*' 2>/dev/null
```

אחד. הערכה כבר ב-`~/makers-bonuses`: זו התקנה קודמת או שכפול קודם. עדכן אותה ועבוד בה: `git -C ~/makers-bonuses pull --ff-only`. אם זו לא תיקיית גיט, כי היא הגיעה מזיפ, אין מה לעדכן.

שתיים. הוא גרר לתוך `3-work/in/` את התיקייה `ig-dm-automation-kit` מהזיפ: הוצא אותה משם אל המקום הקבוע. העברה ולא העתקה, כי מה שמשמש עבודה לא נשאר ב-`in/`, וערכה עם קוד לא נכנסת ל-`_process/`. התיקייה שמעל `ig-dm-automation` היא זו שעוברת:

```bash
mv "<התיקייה שמעל ig-dm-automation>" ~/makers-bonuses
```

שלוש. אין אותה באף אחד מהשניים: משכפלים למקום הקבוע.

```bash
git clone https://github.com/themakers-y-d/makers-bonuses.git ~/makers-bonuses
```

ובשורה אחת לבעלים, בעברית: "הערכה יושבת אצלך ב-makers-bonuses בתיקיית הבית, מחוץ למערכת, וכל ההתקנה רצה משם."

### שלב 0.1, מה לקרוא, ו-Node

`04-gotchas.md` עד הסוף. אלה הכללים שמונעים את התקלות, ורובן לא מחזירות שגיאה.

ובדוק `node --version`. ‏18 ומעלה, ממשיכים.

חסר או ישן מדי: **קודם אומרים לו, ושום דבר לא מותקן בלי כן שלו.** במשפט אחד: "חסר במחשב Node, המנוע שהכלי רץ עליו. אפשר להתקין אותו עכשיו, זה חינם ולוקח כמה דקות. להתקין?" רק אחרי כן:

• **במק:** אם יש Homebrew (`command -v brew`), תגיד לו שאתה מריץ `brew install node`, ושזה לוקח עד כמה דקות של שקט. אם אין, שלח אותו ל-nodejs.org, לכפתור של גרסת ה-LTS, ותגיד לו שההתקנה תבקש את סיסמת המחשב שלו ושזה תקין.

• **בווינדוס:** `winget install -e --id OpenJS.NodeJS.LTS --accept-source-agreements --accept-package-agreements`. תגיד לו לפני ההרצה שיקפוץ חלון שמבקש אישור, ושם לוחצים כן. אם אין `winget` או שההתקנה נכשלה, nodejs.org וגרסת ה-LTS.

אחרי התקנה, Node נראה רק בחלון חדש של קלוד קוד. זה מסתדר לבד, כי שלב 0.5 ממילא סוגר ופותח, ושם תבדוק שוב.

**כשהוא חוזר:** קרא את הסמן, ואת הקובץ הזה מהשלב שהסמן נוקב בו. אל תתחיל מחדש ואל תשאל אותו איפה הערכה: היא ב-`~/makers-bonuses`. בדוק שוב `node --version`, ואמור לו בשורה אחת שאתה ממשיך מאיפה שעצרתם.

מכאן הסקיל `connect-ig-dm` הוא מקור האמת, והוא יירה לבד בפעם הבאה שהבעלים יבקש. הקובץ הזה הוא ההרצה של עכשיו.

### שלב 1, שורת המהלך

ואז טען את `/connect-a-tool` והמשך לשלב 2. עם ווייבקודר הוא טוען אותו שוב בחלון שלו, כי שם החיבור קורה.

### שלב 3, חשבון Zernio ומפתח

קודם הכן את הקובץ שהמפתח ייכנס אליו, ורק אחר כך שלח אותו להירשם. המפתח מוצג פעם אחת בלבד, וצריך מקום להדביק אותו ברגע שהוא מופיע.

במק או ב-Git Bash:

```bash
mkdir -p ~/.config/ig-dm && touch ~/.config/ig-dm/zernio.env && chmod 600 ~/.config/ig-dm/zernio.env
```

בווינדוס בלי Git Bash, ב-PowerShell:

```powershell
$d="$HOME\.config\ig-dm"; New-Item -ItemType Directory -Force $d | Out-Null; if (!(Test-Path "$d\zernio.env")) { New-Item -ItemType File "$d\zernio.env" | Out-Null }
```

שם אין צורך ב-chmod, כי תיקיית המשתמש בווינדוס כבר פרטית לו.

שורה אחת בקובץ: `ZERNIO_API_KEY=sk_...`

פתח לו את הקובץ בעורך טקסט: במק `open -e ~/.config/ig-dm/zernio.env`, בווינדוס `notepad "$HOME/.config/ig-dm/zernio.env"` (עובד גם ב-Git Bash וגם ב-PowerShell). תגיד לו מראש שייפתח חלון ריק, ושישאיר אותו פתוח.

עכשיו שלח אותו ל-zernio.com/signup. גוגל הוא המהיר ביותר. תגיד לו **לפני** שהוא נרשם שמיד אחרי ההרשמה מוצג מפתח פעם אחת בלבד: ברגע שהוא מופיע הוא מעתיק אותו לחלון הפתוח, בשורה אחת בצורה `ZERNIO_API_KEY=sk_...`, שומר עם Cmd+S במק או Ctrl+S בווינדוס, וסוגר.

לא ב-iCloud, לא ב-OneDrive, לא ב-Dropbox, לא בכונן חיצוני. ככה המפתח לא מסתנכרן לשום ענן ונשאר רק על המחשב הזה.

עדכן בסמן: "עצרנו: שלב 3, הבעלים נרשם ל-Zernio ומדביק את המפתח לקובץ."

### שלב 4, חיבור אינסטגרם

בדשבורד של Zernio, עמוד Connections, הוא בוחר Instagram.

במסך האישור יש חמישה מתגים. תגיד לו לכבות שניים: פרסום תוכן, ותובנות. נשארים דלוקים: פרופיל ומדיה, תגובות, והודעות.

הוא לוחץ Allow. זה הקליק שלו.

ועכשיו, לפני כל פקודה, הנוסחים. קרא את `02-rules.md` לפני בחירת מצב ההתאמה, ואת `03-copy.md` לפני כתיבת נוסח. הנוסחים נכתבים **איתו**, לא בשבילו, כאן בשיחה: זה הטקסט שזרים יקראו בשמו. אם המילה שבחר קצרה מדי למצב ההתאמה, תגיד לו עכשיו ותציע חלופה.

### שלב 5, הוכחת חיבור ובניית החוקים

בלי ווייבקודר, אתה מריץ:

```bash
cd ~/makers-bonuses/ig-dm-automation
node kit/zernio.mjs doctor
```

חייב לחזור עם שם המשתמש שלו באינסטגרם. שם המשתמש על המסך הוא הוכחה. "מחובר" הוא טענה. מה שאומרים לו: "החיבור עובד: אני רואה את החשבון @<שם המשתמש>."

ואז החוקים. העתק את `kit/automations.example.json` ל-`kit/automations.json` ומלא לפי התשובות והנוסחים שסוכמו: `cp kit/automations.example.json kit/automations.json`. ‏`platformPostId` נשאר `null`, כדי שהחוק יכסה גם את הפוסטים שעוד לא עלו.

```bash
node kit/selfcheck.mjs
node kit/zernio.mjs plan
```

ירוק ב-selfcheck, ואומרים: "בדקתי את החוקים, הם תקינים." את התוכנית אתה מראה לו בעברית: המילה, מצב ההתאמה, אם יש שער עוקבים, והנוסחים כמו שייצאו. ורק אחרי כן שלו, שלב 6.

בווינדוס ב-PowerShell, אם העברית בפלט נראית משובשת, הראה לו את הנוסחים מתוך `kit/automations.json` ולא את פלט הטרמינל.

**עם ווייבקודר, זו ההעברה הראשונה.** לפניה, שורה אחת לבעלים: "עכשיו הווייבקודר שלך בודק את החיבור ובונה את החוקים. זה לוקח כמה דקות, ובזמן הזה יהיה פה שקט, וזה תקין." בבריף אליו: הנתיב `~/makers-bonuses/ig-dm-automation`, שלוש התשובות, הנוסחים שסוכמו מילה במילה, ושהבעלים כבר אישר את המהלך הזה בשיחה, כך שאין צורך לחכות לכן נוסף. התפקיד שלו: `doctor`, בניית `kit/automations.json` כמו שתואר למעלה, `selfcheck` ו-`plan`, **בלי `--apply`**. הוא מחזיר את שם המשתמש שחזר ואת פלט התוכנית. ואם משהו דורש את הבעלים, הוא עוצר ומחזיר את השאלה. אתה מראה לבעלים את שם המשתמש ואת התוכנית בעברית, ומחכה לכן.

### שלב 6, שליחה לשרת

רק אחרי כן מפורש על התוכנית:

```bash
node kit/zernio.mjs sync --apply
node kit/zernio.mjs list
```

ה-id של כל חוק מופיע ב-`list`, וממנו לוקחים את `<id>` בפקודות הבאות ובשורת הכיבוי.

עם ווייבקודר, זה חלק מההעברה השנייה, בשלב 7.

### שלב 7, קוראים חזרה מהשרת

```bash
node kit/zernio.mjs get <id>
```

ודא שהשער, הכפתורים והווריאציות באמת שם. שדה שנבלע בשקט לא מחזיר שגיאה, הוא מחזיר ליד אחד שלא קיבל הודעה חודש אחר כך. מה שאומרים לו: "החוק נוצר בחשבון שלך, וקראתי אותו חזרה מהשרת: המילה, הנוסחים והשער שם."

**עם ווייבקודר, זו ההעברה השנייה**, אחרי הכן שלו על התוכנית. שורה לבעלים לפני: "הווייבקודר שולח עכשיו את החוק לחשבון שלך וקורא אותו חזרה. כמה דקות של שקט." בבריף: שהבעלים אישר את התוכנית שהוחזרה בהעברה הראשונה, ושהתפקיד הוא `sync --apply`, `list` ו-`get <id>`, והחזרת ה-id ומה שחזר מהשרת.

### שלב 8, בדיקה חיה, ובלעדיה לא סיימת

תגובה של הבעלים על הפוסט של עצמו לא מפעילה כלום. צריך אדם אחר.

הוא מבקש מחבר להגיב את המילה על ריל אמיתי, ואומר לך כשהחבר הגיב. ואז:

```bash
node kit/zernio.mjs logs <id>
```

רק כשיש שם שורה עם משלוח מוצלח, זה נגמר. עד אז התצורה נכונה והמסירה לא מוכחת, והשניים נראים זהים מבפנים. מה שאומרים לו: "<השם> קיבל את ההודעה, ב-<השעה>." ואם אין שורה: "עוד לא רואה משלוח. בוא נבדוק שהתגובה נכתבה אחרי שהחוק נוצר, ובחשבון אחר משלך."

**עם ווייבקודר, זו ההעברה השלישית**, אחרי שהבעלים אמר שהחבר הגיב. שורה לבעלים לפני: "הווייבקודר בודק עכשיו שההודעה יצאה, ורושם את החיבור אצלך. כמה דקות של שקט." בבריף: ה-id, הנתיב המלא של `ig-dm-automation`, ושלושה תפקידים: `logs <id>` והחזרת השורה, השורה ב-`tools.md` דרך `/connect-a-tool` כמו שכתוב בשלב 9, ו-`/ship-it-live`.

### שלב 9, סגירה

`/ship-it-live` רץ כי זה נגע בחשבון חי ושלח הודעות לאנשים אמיתיים, ו-`/final-pass` לפני שמוסרים לו משהו.

שורה אחת נוספת ל-`tools.md` בשורש המערכת, דרך `/connect-a-tool`, על ידי מי שהכלל במערכת שלו נוקב בשמו: אינסטגרם תגובה-להודעה, גישת קריאה וכתיבה, התאריך, וכיבוי. בשורת הכיבוי כתוב את פקודת ה-pause עם הנתיב המלא של תיקיית `ig-dm-automation` וה-id האמיתי של החוק, לא `<id>`, כדי שסשן עתידי שנפתח בשורש המערכת יריץ אותה כמו שהיא. שורה אחת בטבלה הקיימת, בלי לשכתב את הקובץ.

הקובץ עם מילות המפתח והנוסחים נשמר ב-`3-work/now/ig-dm/` עם שם מתוארך, והבעלים יודע איפה הוא. ומחק את הסמן: `rm 3-work/now/ig-dm/_process/install-in-progress.md`. ההתקנה נגמרה, והסשן הבא לא צריך לחשוב שהיא באמצע.

ותגיד לו את דרך החזרה, כי זה מרגיע וזה נכון:

```bash
node kit/zernio.mjs pause <id> --apply
```

מפסיק כל שליחה מיד בלי לפרק כלום, ו-`resume` מחזיר.

מה שנלמד עובר לארכיונאי כשורה מוצעת, לא נכתב ישירות.
