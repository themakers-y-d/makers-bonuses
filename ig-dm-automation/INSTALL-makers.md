# מורטי, זה אליך

הבעלים הביא מתנה של MAKERS להתקנה. הקובץ הזה כתוב אליך כדי שלא תצטרך להבין לבד מה לעשות. הבעלים לא צריך לקרוא אותו.

## מה זה, בשורה אחת

מישהו מגיב מילה על ריל או עונה לסטורי, ומקבל הודעה פרטית עם הלינק. אופציונלית רק אחרי שהוא עוקב.

המנוע הוא Zernio, שותפה רשמית של מטא. אין אפליקציית מטא לפתוח, אין שרת, אין מסד נתונים ואין טוקן לתחזק.

## ההחלטות שכבר נעשו בשבילך

אל תבזבז עליהן שאלות.

**הסוכן:** ה-Vibecoder. זו עבודה שצריכה לרוץ ולהתחבר לחשבון אמיתי, כלומר בדיוק ההגדרה שלו. תגיד את שורת המהלך ותעביר.

**הפרויקט:** `3-work/now/ig-dm/`. אם התיקייה כבר קיימת, עובדים בתוכה ולא יוצרים תאומה לידה.

**הסקילים שנטענים:** ‏`/connect-a-tool` (זו התחברות לחשבון חי) ובסוף `/ship-it-live` (זה נוגע בחשבון אמיתי ושולח הודעות לאנשים).

**השאלות:** שלוש, כתובות מילה במילה בשלב 2. שאל אותן בגל אחד ואל תוסיף עליהן.

**מה נשמר בסוף:** קובץ עם מילות המפתח והנוסחים ב-`3-work/now/ig-dm/` עם שם מתוארך, והבעלים יודע איפה הוא.

## שלושה כללים שלא כדאי לעקוף

**שתי פעולות הן של הבעלים ולא שלך:** ההרשמה ל-Zernio, ואישור חיבור האינסטגרם. שתיהן מעניקות גישה לחשבון שלו, וסוכן לא מאשר גישה לחשבון של מישהו אחר. תגיד לו בדיוק על מה ללחוץ ותחכה.

**המפתח לא עובר בצ׳אט.** הוא מוצג פעם אחת על המסך שלו והוא מדביק אותו לקובץ בעצמו. אל תדפיס אותו, גם לא בהודעת שגיאה.

**אין `--apply` לפני שהראית לו את התוצאה בלי `--apply`.**

## סדר העבודה

### שלב 0, איפה השכפול נחת

הבעלים כנראה פתח את קלוד קוד בתוך המערכת, כי זה המקום שהוא מכיר. בדוק את התיקייה הנוכחית: אם יש בה `.claude/` או `1-me/` או `2-makers/`, אתה בתוך המערכת שלו.

במקרה כזה תגיד משפט אחד ותעבור החוצה:

```bash
cd ~ && git clone https://github.com/themakers-y-d/makers-bonuses.git && cd makers-bonuses
```

הערכה חיה בתיקייה משלה. ריפו שלם בתוך המערכת מבלבל אותה ומקשה עליו לנקות אחר כך.

כל פקודות `node kit/...` בקובץ הזה רצות מתוך `<השכפול>/ig-dm-automation`, אז היכנס אליה עכשיו: `cd ~/makers-bonuses/ig-dm-automation`. אם המעטפת חוזרת לתיקיית המערכת, הרץ אותן עם הנתיב המלא.

### שלב 0.1, מה לקרוא לפני

`04-gotchas.md` עד הסוף. אלה הכללים שמונעים את התקלות, ורובן לא מחזירות שגיאה.

ובדוק `node --version`. אם חסר או מתחת ל-18, אל תשלח אותו לחפש: תגיד לו במשפט שזה המנוע שהכלי רץ עליו, תן את nodejs.org, וחכה שיגיד שסיים. בווינדוס `node --version` יראה אותו רק אחרי הסגירה והפתיחה של שלב 0.5, אז שם תבדוק שוב.

### שלב 0.5, מתקינים את הסקיל קודם

זה הצעד שהופך התקנה חד פעמית ליכולת קבועה, והוא ראשון בכוונה.

```bash
cp -R skills/connect-ig-dm "<נתיב המערכת שלו>/.claude/skills/"
```

ואז תגיד לו לסגור ולפתוח מחדש את קלוד קוד. סקילים נטענים רק בעלייה. בווינדוס זו סגירה מלאה של קלוד קוד, כי גם Node שהותקן בשלב 0.1 נראה רק בחלון חדש, ואחרי שהוא חוזר תבדוק שוב `node --version`.

אחרי שהוא חוזר, הסקיל `connect-ig-dm` הוא מקור האמת והוא יירה לבד בפעם הבאה שהבעלים יבקש. הקובץ הזה הוא ההרצה של עכשיו.

### שלב 1, שורת המהלך והעברה ל-Vibecoder

שורה אחת לבעלים, כמו בכל עבודה: מה אתה עושה ולמי אתה מעביר. ואז מעביר.

מכאן ואילך ה-Vibecoder מבצע, בחלון שלו, עם `/connect-a-tool` טעון.

### שלב 2, שלוש השאלות, בגל אחד

• חשבון האינסטגרם שלך מוגדר Business או Creator?

• איזו מילה אנשים יגיבו, ולאן הלינק שולח?

• רוצה שרק עוקבים יקבלו את הלינק, או שכולם?

אם החשבון פרטי, עוצרים כאן. חשבון פרטי לא נותן גישה לתגובות ולהודעות, ואין מסלול עוקף. שולחים אותו להפוך אותו ליוצר בהגדרות אינסטגרם, זה חינם ולוקח דקה.

### שלב 3, חשבון Zernio ומפתח

קודם הכן את הקובץ שהמפתח ייכנס אליו, ורק אחר כך שלח אותו להירשם. המפתח מוצג פעם אחת בלבד, וצריך מקום להדביק אותו ברגע שהוא מופיע.

במק או ב-Git Bash:

```bash
mkdir -p ~/.config/ig-dm && touch ~/.config/ig-dm/zernio.env && chmod 600 ~/.config/ig-dm/zernio.env
```

בווינדוס בלי Git Bash, ב-PowerShell:

```powershell
$d="$HOME\.config\ig-dm"; New-Item -ItemType Directory -Force $d | Out-Null; if (!(Test-Path "$d\zernio.env")) { New-Item -ItemType File "$d\zernio.env" | Out-Null }
```

שם אין צורך ב-chmod, כי תיקיית המשתמש בווינדוס כבר פרטית לו.

שורה אחת בקובץ: `ZERNIO_API_KEY=sk_...`

פתח לו את הקובץ בעורך טקסט: במק `open -e ~/.config/ig-dm/zernio.env`, בווינדוס `notepad "$HOME/.config/ig-dm/zernio.env"` (עובד גם ב-Git Bash וגם ב-PowerShell). תגיד לו מראש שייפתח חלון ריק, ושישאיר אותו פתוח.

עכשיו שלח אותו ל-zernio.com/signup. גוגל הוא המהיר ביותר. תגיד לו **לפני** שהוא נרשם שמיד אחרי ההרשמה מוצג מפתח פעם אחת בלבד: ברגע שהוא מופיע הוא מעתיק אותו לחלון הפתוח, בשורה אחת בצורה `ZERNIO_API_KEY=sk_...`, שומר עם Cmd+S במק או Ctrl+S בווינדוס, וסוגר.

לא ב-iCloud, לא ב-OneDrive, לא ב-Dropbox, לא בכונן חיצוני. ככה המפתח לא מסתנכרן לשום ענן ונשאר רק על המחשב הזה.

### שלב 4, חיבור אינסטגרם

בדשבורד של Zernio, עמוד Connections, הוא בוחר Instagram.

במסך האישור יש חמישה מתגים. תגיד לו לכבות שניים: פרסום תוכן, ותובנות. נשארים דלוקים: פרופיל ומדיה, תגובות, והודעות.

הוא לוחץ Allow. זה הקליק שלו.

### שלב 5, הוכחת חיבור לפני שבונים משהו

```bash
node kit/zernio.mjs doctor
```

חייב לחזור עם שם המשתמש שלו באינסטגרם. שם המשתמש על המסך הוא הוכחה. "מחובר" הוא טענה.

### שלב 6, בונים את החוקים

העתק את `kit/automations.example.json` ל-`kit/automations.json` ומלא לפי התשובות: `cp kit/automations.example.json kit/automations.json`.

קרא את `02-rules.md` לפני בחירת מצב התאמה, ואת `03-copy.md` לפני כתיבת נוסח. הנוסחים נכתבים **איתו**, לא בשבילו. זה הטקסט שזרים יקראו בשמו.

`platformPostId` נשאר `null`, כדי שהחוק יכסה גם את הפוסטים שעוד לא עלו.

```bash
node kit/selfcheck.mjs
node kit/zernio.mjs plan
```

הראה לו את התוכנית, ורק אז `node kit/zernio.mjs sync --apply`.

בווינדוס ב-PowerShell, אם העברית בפלט נראית משובשת, הראה לו את הנוסחים מתוך `kit/automations.json` ולא את פלט הטרמינל.

### שלב 7, קוראים חזרה מהשרת

ה-id של כל חוק מופיע ב-`node kit/zernio.mjs list`, וממנו לוקחים את `<id>` בפקודות למטה ובשורת הכיבוי.

```bash
node kit/zernio.mjs get <id>
```

ודא שהשער, הכפתורים והווריאציות באמת שם. שדה שנבלע בשקט לא מחזיר שגיאה, הוא מחזיר ליד אחד שלא קיבל הודעה חודש אחר כך.

### שלב 8, בדיקה חיה, ובלעדיה לא סיימת

תגובה של הבעלים על הפוסט של עצמו לא מפעילה כלום. צריך אדם אחר.

הוא מבקש מחבר להגיב את המילה על ריל אמיתי, ואז:

```bash
node kit/zernio.mjs logs <id>
```

רק כשיש שם שורה עם משלוח מוצלח, זה נגמר. עד אז התצורה נכונה והמסירה לא מוכחת, והשניים נראים זהים מבפנים.

### שלב 9, סגירה

`/ship-it-live` רץ כי זה נגע בחשבון חי ושלח הודעות לאנשים אמיתיים, ו-`/final-pass` לפני שמוסרים לו משהו.

שורה אחת נוספת ל-`tools.md` בשורש המערכת: אינסטגרם תגובה-להודעה, גישת קריאה וכתיבה, התאריך, וכיבוי. בשורת הכיבוי כתוב את פקודת ה-pause עם הנתיב המלא של תיקיית `ig-dm-automation` וה-id האמיתי של החוק, לא `<id>`, כדי שסשן עתידי שנפתח בשורש המערכת יריץ אותה כמו שהיא. שורה אחת בטבלה הקיימת, בלי לשכתב את הקובץ.

הקובץ עם מילות המפתח והנוסחים נשמר ב-`3-work/now/ig-dm/` עם שם מתוארך, והבעלים יודע איפה הוא.

ותגיד לו את דרך החזרה, כי זה מרגיע וזה נכון:

```bash
node kit/zernio.mjs pause <id> --apply
```

מפסיק כל שליחה מיד בלי לפרק כלום, ו-`resume` מחזיר.

מה שנלמד עובר לארכיונאי כשורה מוצעת, לא נכתב ישירות.
