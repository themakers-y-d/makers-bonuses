# ההקמה, ומה בעצם קורה כאן

## התמונה במשפט

ManyChat הוא שלושה דברים: מקשיב לתגובות, שולח הודעה פרטית, ומנהל שיחה קצרה עם כפתורים. שלושתם קריאות רשת. הממשק היפה יושב מעליהן.

מה שהיה חסר זה מישהו שיכתוב את הקריאות, וזה בדיוק מה שקלוד עושה כאן.

## למה זה לא רץ ישירות מול מטא

אפשר לבנות את זה ישירות מול מטא, וזו הדרך שבה הגרסה הקודמת של המדריך הזה עבדה. היא דרשה אפליקציית מטא, שרת, מסד נתונים, וטוקן שמתחדש.

והיא נתקעה בשתי נקודות: **תשובות לסטורי ובדיקת עוקבים** דורשות הרשאה שמטא נותנת רק אחרי App Review, תהליך של שבועות עם סרטוני הדגמה ובדיקה אנושית.

Zernio היא שותפה רשמית של מטא, וההרשאה הזו כבר אצלה. כשאתה מחבר אליה את החשבון שלך, אתה משתמש באישור שלה. זה כל הטריק, ובזכותו הסטורי ושער העוקבים עובדים ביום הראשון.

## מה יש לך אחרי ההתקנה

חשבון Zernio עם חשבון האינסטגרם שלך מחובר אליו.

מפתח API בקובץ אחד על המחשב, ב-`~/.config/ig-dm/zernio.env`. הוא לא בריפו ולא בתיקייה מסונכרנת, ובכוונה.

תיקיית `kit/` עם סקריפט אחד וקובץ הגדרות. כל מה שמשתנה יושב ב-`automations.json`, ואף פעם לא בתוך הקוד.

## ההרשאות שביקשנו, ומה לא ביקשנו

במסך האישור של אינסטגרם יש חמישה מתגים. השארנו שלושה: פרופיל ומדיה, תגובות, והודעות.

כיבינו שניים: פרסום תוכן, ותובנות. המערכת לא צריכה אותם. אם יום אחד תרצה שהכלי גם יפרסם בשבילך, תחבר מחדש ותדליק.

הכלל הפשוט: אל תיתן הרשאה שאתה לא משתמש בה. אם משהו ישתבש אצל הצד השני, זה הגבול של הנזק.

## הפקודות שתשתמש בהן

```bash
node kit/zernio.mjs doctor      # המפתח תקין? החשבון מחובר? הקונפיג שפוי?
node kit/zernio.mjs plan        # מה ישתנה. בלי לכתוב כלום
node kit/zernio.mjs sync --apply
node kit/zernio.mjs list        # מה חי עכשיו, כולל כמה נשלחו
node kit/zernio.mjs logs <id>   # מי הגיב, מה כתב, והאם ההודעה יצאה
node kit/zernio.mjs pause <id> --apply
```

כל פקודה מדפיסה מה היא עומדת לעשות לפני שהיא עושה. כתיבה היא תמיד dry run עד שמוסיפים `--apply`, ומחיקה דורשת גם `--yes`.

## אם משהו נשבר, קודם כל

```bash
node kit/zernio.mjs doctor
```

הוא אומר לך בשורה אחת אם הבעיה במפתח, בחיבור, או בקונפיג. משם `04-gotchas.md`.
