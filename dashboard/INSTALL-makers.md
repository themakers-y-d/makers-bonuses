# מורטי, זה אליך

⛔ **כל מילה שהבעלים רואה ממך, בעברית.** גם המשפט הקצר לפני פקודה, גם עדכון באמצע, וגם התוצאה של בדיקה.

הבעלים הוריד את ערכת הדאשבורד של MAKERS ואמר לך איפה היא. הקובץ הזה כתוב אליך כדי שלא תצטרך להמציא סדר. הבעלים לא צריך לקרוא אותו.

## מה זה, בשורה אחת

בסוף לבעלים יש דאשבורד באינטרנט, בכתובת משלו, עם הנתונים שלו במסד נתונים שלו, שנפתח רק אחרי התחברות ורק אליו. ובפעם הבאה שהוא אומר "נכנסה פנייה", אתה רושם אותה בלי לחזור לכאן.

## ההחלטות שכבר נעשו בשבילך

אל תבזבז עליהן שאלות.

**מי מבצע, לפי המערכת שלו ולא נגדה:** בגרסאות קודמות של המערכת יש מייקר בשם הווייבקודר, ובחדשות אין. שלב 0 בודק את זה, ושני המצבים תקינים.

• **בלי ווייבקודר:** אתה מבצע הכל בעצמך, בשיחה הראשית, כולל כל פקודה.

• **עם ווייבקודר:** במערכת הזו הכלל הוא שמה שרץ ומתחבר לחשבון חי עובר אליו, ואתה עובד לפי הכלל הזה. הבעלים נדרש באמצע כעשר פעמים, והווייבקודר עובד בחלון משלו ולא יכול לשאול אותו כלום. לכן הכל עם הבעלים נשאר אצלך בשיחה: השאלות, ההרשמות, ההדבקות בעורך, אישור השורות, הכניסה, והתיקונים שלו. ומה שרץ בלי שיחה עובר לווייבקודר בארבע העברות קבועות, שכתובות בסעיף שלהן למטה.

**תיקיית הקוד:** `~/makers-dashboard`, בתיקיית הבית, מחוץ למערכת. בווינדוס `$HOME\makers-dashboard`. שם יושב הקוד של כל העמודים מהיום ולתמיד.

**הפרויקט במערכת:** `3-work/now/dashboard/`. אם התיקייה כבר קיימת, עובדים בתוכה ולא יוצרים תאומה לידה. קוד לא נכנס לשם, רק קבצים מתוארכים.

**המפתח הסודי:** בקובץ `~/.config/makers-dashboard/supabase.env`, בשורה אחת. לא בתיקיית הקוד, לא במערכת, ולא בצ׳אט.

**הסקילים שנטענים:** כל אחד על ידי מי שהכלל במערכת שלו נוקב בשמו. `/connect-a-tool` בשלב 1, כי זו התחברות לשני חשבונות חיים. `/ship-it-live` לפני הפריסה בשלב 9, כי הדף מחזיק נתוני לקוחות. `/build-skill` בשלב 13, כדי שהרישום יעבוד בפעם הבאה. `/final-pass` בשלב 14.

**השאלות:** שלוש, כתובות מילה במילה בשלב 2. שאל אותן בגל אחד ואל תוסיף עליהן. מי הוא ואיך כסף נכנס אצלו כבר כתוב ב-`1-me/`, אז את זה לא שואלים.

**מה נשמר בסוף:** קובץ אחד ב-`3-work/now/dashboard/` עם שם מתוארך, טקסט רגיל בלי עטיפת כיווניות, והבעלים יודע איפה הוא.

**כל מה שהבעלים קורא, בעברית.** גם משפט לפני פקודה, גם עדכון באמצע וגם תוצאה של בדיקה. פלט באנגלית לא מודבק לו, אתה אומר אותו במשפט עברי.

## סדר העבודה

### שלב 0, איפה הערכה ואיפה אתה

קודם המצב. מתוך שורש המערכת:

```bash
[ -d 2-makers/vibecoder ] && echo "מצב: עם ווייבקודר" || echo "מצב: בלי ווייבקודר"
```

השורה הזו קובעת מי מבצע מה. אל תשאל אותו על זה ואל תעצור על זה.

ואז מערכת ההפעלה: `uname -s`. ‏`Darwin` זה מק. ‏`MINGW` או `MSYS` זה ווינדוס עם Git Bash, וכל פקודות ה-bash כאן רצות שם כמו שהן. אם אין לך bash בכלל, אתה ב-PowerShell, ולכל פקודה שזה משנה בה משהו כתובה כאן גם גרסת PowerShell.

ובדוק `node --version`. ‏20 ומעלה, ממשיכים. חסר או ישן מדי: **קודם אומרים לו, ושום דבר לא מותקן בלי כן שלו.** במשפט אחד: "חסר במחשב Node, המנוע שהפקודה של וורסל רצה עליו. הוא נדרש רק בשלב הפריסה, אז אפשר להתקין אותו עכשיו במקביל. להתקין?" רק אחרי כן:

• **במק:** אם יש Homebrew (`command -v brew`), תגיד לו שאתה מריץ `brew install node` ושזה לוקח כמה דקות של שקט. אם אין, שלח אותו ל-nodejs.org, לכפתור של גרסת ה-LTS, ותגיד לו שההתקנה תבקש את סיסמת המחשב שלו ושזה תקין.

• **בווינדוס:** `winget install -e --id OpenJS.NodeJS.LTS --accept-source-agreements --accept-package-agreements`. תגיד לו לפני ההרצה שיקפוץ חלון שמבקש אישור, ושם לוחצים כן. אם אין `winget` או שההתקנה נכשלה, nodejs.org וגרסת ה-LTS.

בשלב 9 אתה בודק שוב. בווינדוס צריך לסגור ולפתוח מחדש את קלוד קוד אחרי ההתקנה, אחרת החלון הפתוח לא רואה את Node, ו-`claude --continue` מחזיר אותו לאותה שיחה. לא מתקינים את וורסל גלובלית: כל פקודת `vercel` כאן רצה כ-`npx vercel`.

הערכה מגיעה אליך כמו כל דבר שהבעלים מביא: הוא גורר את התיקייה אל `3-work/in/`, או גורר אותה לצ׳אט ואז הנתיב שלה כבר מולך. אל תחפש אותה בהורדות או בשאר המחשב. אם היא לא באחד משני המקומות, תבקש ממנו לגרור אותה ל-`3-work/in/` ותחכה.

חפש את התיקייה שבה יושב הקובץ הזה, ולא רק את השם, כי חילוץ בווינדוס יוצר לפעמים תיקייה בתוך תיקייה באותו שם. מתוך שורש המערכת:

```bash
find 3-work/in -maxdepth 3 -name INSTALL-makers.md
```

ב-PowerShell:

```powershell
Get-ChildItem 3-work\in -Recurse -Depth 2 -Filter INSTALL-makers.md | Select-Object -ExpandProperty DirectoryName
```

הוצא אותה מ-`3-work/in/` אל תיקיית הקוד. העברה ולא העתקה: הכלל של `in/` במערכת שלו הוא שמה שמשמש עבודה יוצא משם, ובדרך כלל אל `_process/` של הפרויקט. ערכה עם קוד ותיקיות משנה היא היוצא מן הכלל, והיא עוברת לתיקיית הקוד. ב-`3-work/now/dashboard/_process/` נשארת שורה אחת שאומרת לאן היא עברה, כשאתה פותח את הפרויקט בשלב 1. אם `~/makers-dashboard` כבר קיימת, זו ריצה קודמת שלו: עבוד בה, אל תדרוס אותה, ותגיד לו שהעותק החדש נשאר ב-`in/` עד שיחליט.

```bash
[ -e ~/makers-dashboard ] || mv "<התיקייה שמצאת>" ~/makers-dashboard
```

```powershell
if (!(Test-Path "$HOME\makers-dashboard")) { Move-Item "<התיקייה שמצאת>" "$HOME\makers-dashboard" }
```

אם נשארה ב-`in/` תיקייה ריקה עוטפת מחילוץ בווינדוס, מחק אותה. ותגיד לו במשפט אחד שהערכה יושבת עכשיו ב-`~/makers-dashboard`, מחוץ למערכת, ושכל עמוד שיבקש בעתיד נבנה משם.

### שלב 1, שורת המהלך והפרויקט

שורה אחת לבעלים: אתה בונה איתו דאשבורד, כאן בשיחה הזו, וזה לוקח בערך שעה. עם ווייבקודר, באותה שורה: את החלקים שרצים על החשבונות שלו מריץ הווייבקודר שלו, ולפני כל אחד מהם תגיד לו שיהיה שקט של כמה דקות.

ושורה שנייה, מה זה עושה במחשב ובחשבונות שלו: תיקייה אחת בתיקיית הבית, קובץ מפתח אחד, שני חשבונות חינמיים על שמו, ובמערכת רק תיקיית פרויקט, סקיל אחד ושורה ב-`tools.md`. הערכה הגיעה מבחוץ, אז זה הרגע שבו הוא רואה מה היא מבקשת. ותגיד לו מראש שקלוד קוד יבקש ממנו אישור כמה פעמים בדרך, כי תיקיית הקוד וקובץ המפתח יושבים מחוץ לתיקיית המערכת. לכל בקשה שמזכירה את `makers-dashboard`, ‏`npx vercel` או `supabase` מאשרים. בקשה אחרת שהוא לא מבין: לא מאשר ושואל אותך. חכה לכן שלו, ואז טען את `/connect-a-tool`.

השורה ב-`tools.md` נכתבת רק דרך `/connect-a-tool`, על ידי מי שהכלל במערכת שלו נוקב בשמו. עם ווייבקודר זה הוא, בהעברה הרביעית.

פתח את הפרויקט `3-work/now/dashboard/` ואמור את שמו בשורה אחת, כדי שיוכל לתקן עכשיו ולא בעוד שנה. וכתוב ב-`3-work/now/dashboard/_process/` קובץ קצר בשם `kit.md` עם שורה אחת: הערכה עברה מ-`3-work/in/` אל `~/makers-dashboard`.

### שלב 2, שלוש השאלות, בגל אחד

קרא קודם את `1-me/` כדי לדעת במה הוא עוסק ואיך כסף נכנס אצלו. ואז:

• איזו החלטה אתה מקבל שוב ושוב בלי מספיק מידע?

• אם היה מסך אחד שנפתח לך כל בוקר, מה היית רוצה לראות עליו בלי לחפש?

• איפה הדברים האלה רשומים היום? קובץ, גיליון, מערכת, או בשום מקום מסודר, וכל תשובה טובה.

אם התשובה לשאלה השלישית היא "בשום מקום מסודר", זה לא פותח גל שאלות נוסף. בשלב 7 תבקש ממנו בקשה אחת: לספר במשפט על כל פנייה ומכירה מהחודשיים האחרונים, ואתה רושם.

חזור אליו עם הצעה אחת: "ממה שאמרת, אני מציע שני עמודים, האחד X והשני Y. מסכים?" שניים או שלושה עמודים, לא יותר, וכל אחד עונה על שאלה אחת שלו במילים שלו. הוא מאשר או מתקן, ורק אז ממשיכים.

### שלב 3, הקובץ של המפתח, לפני ההרשמה

המפתח הסודי צריך מקום לנחות בו ברגע שהוא מופיע, אז מכינים את המקום קודם.

```bash
mkdir -p ~/.config/makers-dashboard && touch ~/.config/makers-dashboard/supabase.env && chmod 600 ~/.config/makers-dashboard/supabase.env
```

```powershell
$d="$HOME\.config\makers-dashboard"; New-Item -ItemType Directory -Force $d | Out-Null; if (!(Test-Path "$d\supabase.env")) { New-Item -ItemType File "$d\supabase.env" | Out-Null }
```

בווינדוס אין צורך ב-chmod, כי תיקיית המשתמש כבר פרטית לו.

פתח לו את הקובץ בעורך טקסט: במק `open -e ~/.config/makers-dashboard/supabase.env`, בווינדוס `notepad "$HOME/.config/makers-dashboard/supabase.env"`. תגיד לו מראש שייפתח חלון ריק, ושישאיר אותו פתוח עד שלב 4.

### שלב 4, חשבון סופאבייס, פרויקט ושני ערכים

שלח אותו ל-supabase.com להירשם, ואז ללחוץ **New project**. שם הפרויקט: `dashboard`. האזור: אחד מאזורי אירופה. סיסמת המסד: שייצור אוטומטית וישמור במנהל הסיסמאות, היא לא נדרשת בהמשך. הפרויקט עולה בתוך שתיים עד שלוש דקות, ותגיד לו מראש שזה זמן ההמתנה הרגיל.

שלושה דברים הוא מדביק לך בצ׳אט: המייל שאיתו הוא ייכנס לדאשבורד, וגם שני ערכים ציבוריים: כתובת הפרויקט, שמסתיימת ב-`.supabase.co`, והמפתח הציבורי. שניהם מופיעים בחלון שנפתח מהכפתור **Connect** בראש הפרויקט, ובהגדרות תחת **API Keys**. המפתח הציבורי מתחיל ב-`sb_publishable_`, ובפרויקט ישן הוא ה-`anon` שמתחיל ב-`eyJ`. שניהם תקינים.

ואת המפתח הסודי, באותו עמוד **API Keys**, הוא מעתיק לחלון הפתוח בשורה אחת, ושומר עם Cmd+S במק או Ctrl+S בווינדוס:

```
SUPABASE_SECRET_KEY=sb_secret_...
```

בפרויקט ישן זה ה-`service_role`, ואז השורה מתחילה ב-`SUPABASE_SECRET_KEY=eyJ`. לא בצ׳אט, ולא בשום קובץ אחר.

אתה בודק שהוא שם בלי לראות אותו. הפקודה מדפיסה מספר בלבד, וחייב לחזור 1:

```bash
grep -c '^SUPABASE_SECRET_KEY=.\{20,\}' ~/.config/makers-dashboard/supabase.env
```

### שלב 5, הטבלה, ומיד אחריה שער האבטחה

קרא את `SECURITY.md` לפני שאתה נוגע בהרשאות.

שים את `db/schema.sql` בלוח ההעתקה שלו, כדי שלא יצטרך לפתוח קבצים:

```bash
case "$(uname -s)" in
  Darwin) pbcopy < ~/makers-dashboard/db/schema.sql ;;
  MINGW*|MSYS*|CYGWIN*) powershell.exe -NoProfile -Command "Get-Content -Raw -Encoding UTF8 \"\$HOME\\makers-dashboard\\db\\schema.sql\" | Set-Clipboard" ;;
esac
```

ב-PowerShell: `Get-Content -Raw -Encoding UTF8 "$HOME\makers-dashboard\db\schema.sql" | Set-Clipboard`

בווינדוס לא משתמשים ב-`clip`. הוא משבש עברית, והטבלה מכילה ערכי סטטוס בעברית שהמסד בודק מילה במילה.

הוא פותח **SQL Editor** בסרגל הצד של סופאבייס, לוחץ **New query**, מדביק ולוחץ **Run**. אם סופאבייס מזהיר שבשאילתה יש פעולה הרסנית, זה בגלל שורות ה-`drop policy if exists`, שהן מה שמאפשר להריץ את הקובץ שוב בבטחה. מאשרים ומריצים.

ואז אותו דבר עם `db/verify.sql`, בשאילתה חדשה. זו שאילתה אחת שמחזירה תשע שורות. הוא מעתיק לך את התוצאה לצ׳אט, או מדביק צילום מסך שלה.

**כל תשע השורות חייבות להתחיל ב"ירוק".** אחת אדומה: עצור, תקן לפי `SECURITY.md`, הרץ שוב, ואל תמשיך. הוא לא חייב להבין את השורות, הוא חייב לראות שבדקת.

### שלב 6, המשתמש שלו, לפני הנתונים

בלי השלב הזה שלב 7 נכשל, כי `owner_id` מפנה ל-`auth.users`, וכל שורה לפני שהמשתמש קיים נופלת על מפתח זר.

עכשיו הוא מריץ בעורך שאילתה אחת ומדביק לך את התוצאה:

```sql
select id from auth.users where email = 'המייל-שלו@דוגמה.com';
```

זה **מזהה הבעלים**. רשום אותו, הוא נדרש בשלבים 7 ו-13.

### שלב 7, הנתונים שלו

אם יש לו קובץ או גיליון, קרא אותו והמר בעצמך. אם הוא זרק אותו ל-`3-work/in/`, אחרי השימוש הוא עובר ל-`3-work/now/dashboard/_process/`. אל תבקש ממנו להקליד מחדש דבר שכבר קיים. אם אין לו כלום מסודר, שאל אותו על החודשיים האחרונים ורשום אתה. עשרים שורות אמיתיות שוות יותר ממאתיים מומצאות.

כל שורה מחזיקה את אותם שדות: `owner_id`, `date`, `type` שהוא `lead` או `sale`, `source`, `name`, `amount`, `status`, ואופציונלית `note`. הסטטוס הוא אחד מארבעה בלבד: חדש, בשיחה, נסגר, לא רלוונטי.

כתוב את השורות לקובץ `~/makers-dashboard/import.json`, מערך JSON, עם מזהה הבעלים מפורש בכל שורה. זו הכתיבה הראשונה לחשבון שחובר היום, ו-`/connect-a-tool` דורש לה כן מפורש: הראה לו את השורות בטבלה קצרה בצ׳אט, וחכה לכן. ואז הן נכתבות, בלי ווייבקודר על ידך ועם ווייבקודר בהעברה הראשונה:

```bash
set -a; . ~/.config/makers-dashboard/supabase.env; set +a
curl -sS -o /dev/null -w "%{http_code}\n" -X POST "<כתובת הפרויקט>/rest/v1/entries" \
  -H "apikey: $SUPABASE_SECRET_KEY" -H "Content-Type: application/json" -H "Prefer: return=minimal" \
  --data-binary @"$HOME/makers-dashboard/import.json"
```

חייב לחזור `201`. המפתח נשלח בכותרת `apikey` בלבד, ולא כ-`Authorization: Bearer`, כי המפתחות החדשים אינם JWT.

ב-PowerShell `curl` הוא כינוי לפקודה אחרת, אז שם כותבים `curl.exe`, וטוענים את המפתח ככה:

```powershell
Get-Content "$HOME\.config\makers-dashboard\supabase.env" | ForEach-Object { $k,$v = $_ -split '=',2; if ($k) { Set-Item "env:$k" $v } }
```

ובפקודה עצמה `$env:SUPABASE_SECRET_KEY` במקום `$SUPABASE_SECRET_KEY`.

קיבלת קוד אחר? אל תנסה שוב בלולאה. הדרך השנייה תמיד פתוחה: אותה הכנסה כשאילתה שהוא מדביק בעורך, עם המזהה בשליפה לפי המייל.

```sql
insert into public.entries (owner_id, date, type, source, name, amount, status)
select u.id, v.date, v.type, v.source, v.name, v.amount, v.status
from auth.users u
cross join (values
  (date '2026-09-01','lead','אינסטגרם','רונית',0::numeric,'חדש'),
  (date '2026-09-03','sale','המלצה','דנה',1200::numeric,'נסגר')
) as v(date,type,source,name,amount,status)
where u.email = 'המייל-שלו@דוגמה.com';
```

אחרי `201` קרא אותן חזרה מהשרת והראה לו. זו ההוכחה ש-`/connect-a-tool` מבקש, שורה שלו שחזרה מהחשבון שלו:

```bash
curl -sS "<כתובת הפרויקט>/rest/v1/entries?select=date,type,name,amount,status&order=date.desc&limit=5" -H "apikey: $SUPABASE_SECRET_KEY"
```

ואז מחק את `import.json`. שמות הלקוחות שלו לא צריכים לשכב בקובץ פתוח.

### שלב 9, וורסל, ופריסה ראשונה

טען את `/ship-it-live`. זה מצב שני, כי הדף מחזיק נתוני לקוחות. שלושת המשפטים שלו קלים כאן: מה נשבר הוא שהנתונים נחשפים, ושער האבטחה של שלב 5 הוא מה שמונע את זה. החזרה היא מחיקת הפרויקט בוורסל. וכשל נשמע מעצמו, כי הדף פשוט לא נפתח לו, וזו התשובה לשלב שדורש שכשל יצעק. ואין כאן אוטומציה שמחזיקה עותק יחיד של משהו: הטבלה היא הרשומה עצמה, והיא יושבת בחשבון שלו.

בדוק שוב `node --version`. אם עדיין חסר, כאן מחכים לו.

הוא נרשם ב-vercel.com, ואז אתה מחבר את הפקודה לחשבון שלו. ההתחברות עצמה היא קליק שלו בדפדפן, ולכן בשני המצבים אתה מריץ את הפקודה שמציגה לו את הקישור, כמו שפתחת לו את קובץ המפתח בעורך. עם ווייבקודר, כל מה שאחרי האישור שלו, מ-`whoami` ועד ה-200, הוא ההעברה השנייה, וגם `/ship-it-live` רץ אצלו שם. ההתחברות מחכה לאישור בדפדפן ולכן לא מסתיימת לבד. הרץ אותה ברקע, עם האפשרות של קלוד קוד להריץ ברקע או עם `&` בסוף, ועם יומן:

```bash
npx --yes vercel login > ~/makers-dashboard/.vercel-login.log 2>&1 &
```

בפעם הראשונה `npx` מוריד את וורסל, וזה לוקח עד דקה של שקט. תקרא את היומן כל כמה שניות עד שמופיעה בו שורה עם `https://vercel.com/oauth/device?user_code=`, ותן לו את הקישור. הוא פותח אותו ומאשר. זה הקליק שלו.

אחרי שאמר שאישר:

```bash
npx vercel whoami
```

חייב לחזור שם המשתמש שלו בוורסל, והוא מאשר שזה הוא. שם אחר אומר שאתה עומד לפרוס את העסק שלו לחשבון של מישהו זר, ושם עוצרים.

עכשיו הפריסה, מתוך תיקיית `app`. שם הפרויקט באנגלית, אותיות קטנות ומקפים, למשל `ronit-dashboard`:

```bash
cd ~/makers-dashboard/app
npx vercel project add <שם>
npx vercel link --yes --project <שם>
npx vercel deploy --prod --yes
```

הפריסה לוקחת עד דקה. אל תיקח את הכתובת הראשונה שהיא מדפיסה. זו כתובת של פריסה אחת, היא משתנה בכל פעם, ולרוב חסומה מאחורי התחברות לוורסל. הכתובת היציבה היא הקצרה, בדרך כלל `<שם>.vercel.app`, ועם תוספת קטנה כשהשם תפוס. היא מופיעה בשורה של `Aliased`, ואם לא, `npx vercel inspect <הכתובת שהודפסה>` מראה אותה תחת Aliases.

אם `project add` או `link` נכשלים, אל תיתקע עליהם: `npx vercel deploy --prod --yes` לבד יוצר פרויקט בשם התיקייה, `app`, וזה עובד באותה מידה.

תוכיח בעצמך שאין קיר:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<הכתובת היציבה>
```

חייב לחזור `200`.
